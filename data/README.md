# 出走馬データ

**出走馬の登録は画面からではなく、このディレクトリのファイルを PR で更新して行う。**

> ## ⚠️ `data/races/` に置いたものは本番に入る
>
> `main` にマージされると `.github/workflows/data-import.yml` が
> `data:import:remote` を走らせる。**ここに置いてよいのは本番に入れてよいデータだけ。**
>
> アプリのデプロイとは別系統で、**リリースを待たずに入る**（開催に間に合わせるため）。
> 逆に言うと、ここへの変更はレビューを通った時点で本番行きが確定する。
>
> 書式を確かめたいだけの架空のデータは `data/examples/` にある。
> こちらは既定では読まれない。手元で流すときだけ明示する。
>
> ```bash
> pnpm run data:sql:local -- --dir data/examples
> pnpm exec wrangler d1 execute k-note --local --file .wrangler/import-races.sql
> ```
>
> `data/races/` が空でもエラーにはならない（投入するものが無いだけ）。

予想に使うには開催前の時点で出馬表が入っている必要がある。16頭を毎週手で打つのは
現実的ではないので、人でも AI でも同じ経路 — PR — でデータを入れられるようにしてある。

メモ（note）は利用者が画面から書くもので、こちらの対象外。**投入スクリプトは
メモを書かず、消さない。** 例外は出走しなかった候補の取り下げ（下記「取り下げる」）で、
そのときも付いていたメモは消さずに近況メモへ移す。

YAML は手で書いてもよいが、netkeiba から取ってきて書くコマンドがある（下記「取ってくる」）。

## 書き方

`data/races/<開催日>.yaml`。ファイル名と中の `date` は一致させること。

```yaml
date: 2026-09-26

races:
  - course: 中山 # JRA の10場のみ
    raceNumber: 11
    name: オールカマー
    grade: G2 # G1 / G2 / G3 / L / OP。省略可
    surface: 芝 # 芝 / ダート / 障害
    distance: 2200
    direction: 右 # 右 / 左 / 直線
    entries:
      - horseNumber: 5
        bracket: 3
        name: ホースA # 必須
        jockey: ルメール
        sex: 牡 # 牡 / 牝 / セ
        age: 4 # 出馬表の性齢をそのまま。生年は 開催年 - age
        ref: nk-2022-01234 # 外部ID。あれば最優先の引き当てキーになる
```

必須は `date` / `course` / `raceNumber` / `name`（レース名）と、各出走馬の `name` だけ。
残りは分かる範囲で埋める。あとから追記しても、書かなかった項目の既存の値は消えない。

`age`（馬齢）と `birthYear`（生年）はどちらで書いてもよい。出馬表に載るのは性齢なので
`age` のほうが書き写しやすい。両方書くなら一致していること（食い違うと `data:check` で落ちる）。

### 重賞でなくてよい

**条件戦も同じように入れられる。** 重賞に絞っているのは「今週の重賞」画面だけで、
レース一覧にも馬柱にもその絞り込みは無い。

馬の 1勝クラス の走りにメモを残したいなら、そのレースを登録して、
**気にしている馬だけ**出走馬に入れればよい。全頭そろえる必要はない。

```yaml
date: 2026-05-10
races:
  - course: 東京
    raceNumber: 5
    name: 3歳1勝クラス
    className: 1勝クラス # grade は書かない
    surface: 芝
    distance: 1800
    entries:
      - name: ホースA
        finish: 1
        popularity: 1
        last3f: 33.8
```

`grade` が無いレースは、一覧でも馬柱でも `className` が代わりに出る
（重賞は格の札で足りるが、条件戦は条件そのものがレースの識別子なので）。
`data/races/2026-05-10.yaml` がこの形の実例。

### レース後は結果を追記する

**馬柱（予想画面に出す各馬の過去走）は、過去のレースの出走馬行がそのまま材料になる。**
結果を入れないと、翌週以降の予想画面に空欄の枠だけが並ぶ。

```yaml
entries:
  - horseNumber: 3
    name: ホースA
    jockey: ルメール
    age: 4
    # --- ここから下はレース後に追記 ---
    finish: 1 # 着順。除外・中止なら書かない
    popularity: 2 # 人気
    time: "1:58.4" # タイム。文字列のまま
    margin: "クビ" # 着差。競馬の表記をそのまま
    passing: "5-5-4-2" # 通過順
    last3f: 34.2 # 上がり3F
    weight: 57 # 斤量
    horseWeight: 486 # 馬体重
    horseWeightDiff: 4 # 前走からの増減。負の値もある
    odds: 4.1
```

レース自体の `trackCondition`（馬場状態）と `weather`、`fieldSize`（出走頭数）も、結果と一緒に入れられる。

**`fieldSize` は `entries` の数とは別に書く。** 過去走や条件戦は気にしている馬だけを並べるので、
数えても頭数にならない。取消・除外を除いた、実際に走った頭数を書く。馬柱の2行目に「16頭 3枠5番」と出る。
`past` と `result` が書くので、手で書くことはまずない。着順がこれを超えると `data:check` で落ちる
（馬番は超えてよい。18頭立てで1頭取り消すと、17頭の中に18番がいる）。

```yaml
races:
  - course: 中山
    raceNumber: 11
    name: オールカマー
    trackCondition: 良
    weather: 晴
    fieldSize: 16 # 出走頭数（取消・除外を除く）
    winner: ホースB # 勝ち馬
    runnerUp: ホースA # 2着馬
    entries:
      - name: ホースA
        finish: 2
        timeDiff: 0.2 # 勝ち馬とのタイム差（秒）。勝ち馬は2着との差を負で（-0.2）
```

`winner` / `runnerUp` も頭数と同じく entries とは別に書く（勝ち馬が entries にいるとは限らない）。
馬柱には、負けた走なら勝ち馬、勝った走なら2着馬が `timeDiff` と一緒に出る。

`fieldSize` はマイグレーション 0012、`winner` / `runnerUp` / `timeDiff` は 0013 の列。
**書いた YAML の投入は、本番にマイグレーションが流れるまで落ちる**
（`data-import.yml` はマイグレーションを流さない）。書いていない YAML は列を名指ししないので、今までどおり入る。

**結果は「書けば上書き、書かなければ既存を残す」。** 降着や失格の訂正が YAML から効き、
画面から入れた値を YAML の再投入で消すこともない。
枠・馬番とは扱いが違う（あちらは YAML が正で、いったん NULL に落としてから入れ直す）。

### オッズを出すレース

**`ref`（netkeiba の race_id）と `startTime`（発走時刻）を書いた重賞（G1〜G3）だけ、予想画面にオッズが出る。**
L・OP・条件戦は、書いてあっても取りに行かない。
どちらも `data:fetch entries` が出馬表から書くので、手で書くことはまずない。

```yaml
races:
  - course: 中山
    raceNumber: 11
    name: スプリンターズS
    ref: nk-202606040911 # nk- に race_id（年4桁・場2桁・回2桁・日2桁・R2桁）
    startTime: "15:40" # JST。クォートする
    entries: ...
```

- アプリの Cron が単勝・複勝を30分おきに取りに行き、`race_odds` に書く。期間はG1 は前々日の 18:30、G2・G3 は前日の 18:30 から、どちらも発走まで
  （→ [docs/product.md 第1章「例外 — オッズ」](../docs/product.md)）。YAML にオッズを書く必要は無い
- `data:check` は、race_id の年・場・R がそのレースと合っているかを見る。打ち間違えると別のレースのオッズが付く
- 書かなければ D1 の既存の値を残す（結果の欄と同じ）。`ref` と `startTime` は2つ組で書き換わる
- **この2項目を書いた YAML は、アプリのリリース（マイグレーション 0011）より前に本番へ流せない。**
  `start_time` 列がまだ無いため。書いていない YAML は列に触らないので、リリース前でも流れる
- 結果の `odds`（確定の単勝）とは別物。そちらは今までどおり `result` で入れる

### 三段階で書ける

**枠が決まる前に名前だけで登録し、確定後・レース後と同じファイルを更新していく。**

```yaml
# 月曜: 出走予定馬だけ分かっている
entries:
  - name: ホースA
    jockey: ルメール

# 木曜: 枠が確定したので追記
entries:
  - horseNumber: 5
    bracket: 3
    name: ホースA
    jockey: ルメール
    sex: 牡
    age: 4
```

後者を流しても**馬は二重に作られない**。生年が未設定の行を同じ馬として拾い、
書いた項目だけを埋める。馬番を訂正して入れ替えても通る（下記「投入の性質」）。

3回目がレース後の結果追記で、ここまで入れて1レースぶんが完成する。
差分適用が効くので、更新したファイルだけが流れる。

**枠が決まる前は18頭を超えてよい。** 特別登録の馬をそのまま候補として並べられるように、
1レースの出走馬は40頭まで受け付ける（馬番は 1–18 のまま）。確定したら、出走しない候補を
次の「取り下げる」で外す。

### 取り下げる

**YAML から行を消しても DB の出走馬は消えない**（下記「投入の性質」）。枠が決まって
出走しなかった候補や、登録を回避した馬は、`entries` から外して `withdrawn` に書く。

```yaml
entries:
  - horseNumber: 1
    bracket: 1
    name: ホースA
    ref: nk-2022100001
withdrawn: # 出走しなかった候補
  - name: ホースB
    ref: nk-2022100002
```

投入すると、書いた馬の出走馬行を消す。**付いていたメモは消さずに近況メモへ移す。**

- 出走前メモ・ふりかえりは kind を `horse`（近況）に変え、レースとの紐づきを外す
- どのレースのメモだったかは本文の先頭に書き足す。印（◎など）は近況メモに持てないので、
  そこに文字で残す: `（2026-09-27 中山11R スプリンターズS に出走しなかったため、出走前メモから移しました。印 ◎）`
- 日付（`occurred_at`）はレースの日のまま。馬のタイムラインではその週の位置に並ぶ

`withdrawn` は消さずに残しておいてよい。2回目以降は消す行が無いので何も起きない。
同じ馬を `entries` と `withdrawn` の両方に書くと `data:check` で落ちる。

## 取ってくる

`data:fetch` が netkeiba のページを読んで、`data/races/<開催日>.yaml` を書き換える。
**書くのは YAML までで、D1 には触らない。** コメントや既存の並びは崩さず、触った行だけが差分に出る。

```bash
pnpm run data:fetch races   2026-09-27          # その日のレース一覧（場・R・race_id）
pnpm run data:fetch entries 2026-09-27 中山 11  # 候補（枠順前）/ 枠順（確定後）
pnpm run data:fetch past    2026-09-27 中山 11  # 出走馬の過去5走を、それぞれの開催日のファイルへ
pnpm run data:fetch horses  2026-09-27 中山 11  # 性・馬齢・調教師・父・母
pnpm run data:fetch result  2026-09-27 中山 11  # 着順から馬体重まで・馬場・天候・頭数
```

| 手順      | 上書きするもの                                     | 残すもの               |
| --------- | -------------------------------------------------- | ---------------------- |
| `entries` | 枠・馬番（確定後）・騎手・性齢・斤量・調教師・ref、レースの ref・発走時刻 | 馬名・結果・血統       |
| `past`    | —（空いている項目だけ埋める。頭数・勝ち馬・タイム差もここで入る） | 書いてある値すべて |
| `horses`  | 性・馬齢・調教師・父・母                            | 馬名・レースの値       |
| `result`  | 着順から馬体重まで・タイム差・騎手・枠・馬番・馬場・天候・頭数・勝ち馬・2着馬 | 馬名・基本情報 |

- `entries` は netkeiba の出馬表を正とし、**載っていない行を `withdrawn` に移す**（回避・非当選）
- `past` は JRA の10場のレースだけを数える（地方・海外は YAML に入らないため）。取消・除外も数えない
- `result` は YAML にいる馬だけを更新する。気にしている馬だけを載せた条件戦に、他の馬は足さない
- **馬名は書き換えない。** 食い違ったら警告だけ出す（→「馬名を直す」）
- 騎手・調教師は略さない名前に引き直す（初回だけ各人のページを引き、`node_modules/.cache/race-data/` に覚える）
- 1リクエストごとに1秒あける。21頭の過去走でおよそ30秒かかる。まとめて流すときは `--interval 500` で0.5秒まで縮められる（それより短くはできない）
- `--dir <dir>` で書き込み先を変えられる。試すときは作業用のディレクトリにコピーして渡す

### アプリから取らせる

同じ `entries` を GitHub Actions（`.github/workflows/race-data-fetch.yml`）でも回せる。**書くのは YAML と PR までで、
本番に入るのは人がマージしたとき**なのは手で流すときと同じ。PR ができると Discord の「デプロイ」に知らせる。

- **枠順の定期取得。** アプリの Cron が毎時（JST 10:05〜19:05）、1〜3日後の重賞で馬番がまだ無いレースを
  Actions に頼む。Actions は枠順が確定していなければ何も書かない（`--require-confirmed`）。確定すると PR ができ、
  マージされて馬番が本番に入ると対象から外れる
- **管理画面（`/settings/admin`）の「出走馬を取得」。** これから2週間のレースに1つずつボタンがある。
  枠順の前なら候補、後なら枠順を書く。race_id（`ref`）の無い来週以降のレース（申し送り用の枠）は、
  netkeiba の一覧に出ないので押せない。当週になると押せる
- PR のブランチ（`data-fetch/<日付>-<場><R>R`）は Actions が main から作り直して上書きする。PR に手で直しを足すなら、
  そのあとで同じレースを取り直させないこと
- 過去走・馬の基本情報・結果はアプリからは取らせない。今までどおり手で流す

レース一覧（`races` と、race_id の引き当て）は netkeiba の都合で**当週ぶんしか出ない**。
先の開催のレース番号は JRA の開催番組から取る。重賞でも 11R とは限らない
（2026年の CBC賞は暑熱対策の番組で 7R）。

## 流れ

```bash
pnpm run data:check          # YAML の検証だけ（PR で最初に落ちるのはここ）
pnpm run data:import:local   # ローカル D1 に投入
pnpm run data:import:remote  # 本番 D1 に投入
```

`data:check` は競馬場が JRA10場か、馬番が 1–18 で重複していないか、ファイル名と日付が一致するか、
`age` と `birthYear` が食い違っていないか、`entries` と `withdrawn` に同じ馬がいないか等を見る。
D1 には触れない。

**投入するのは内容が変わったファイルだけ。** 適用済みのハッシュを D1 の `data_import`
テーブルに覚えてあり、突き合わせて差分を出す。変更なしのファイルは `-` 付きで表示され、
SQL には含まれない。

```
- 2026-09-26.yaml  レース 1 / 出走馬 5（変更なし）
✓ 2026-10-03.yaml  レース 1 / 出走馬 2

合計: レース 2 / 出走馬 7 — 流すファイル 1 / 2
```

状態を D1 に置いているのは、**適用状況が投入先ごとに違う**から。ローカルと本番では
進み方が別で、リポジトリ内のファイルでは片方しか表せない。

先に `db:migrate:local` / `db:migrate:remote` を通しておくこと（`data_import` が要る）。
テーブルが無ければ警告を出して全ファイルを対象にするので、止まりはしない。

全部を流し直したいときは `--all` を付ける。

```bash
pnpm run data:sql:local -- --all
pnpm exec wrangler d1 execute k-note --local --file .wrangler/import-races.sql
```

## 投入の性質

生成される SQL は**冪等**。同じファイルを何度流しても結果は変わらない。

| 対象   | 挙動                                                                 |
| ------ | -------------------------------------------------------------------- |
| レース | `(date, course, race_number)` で upsert                              |
| 馬     | 下記のキーで引き当て、無ければ作成。属性は**書けば上書き、書かなければ既存を残す** |
| 出走馬 | `(race_id, horse_id)` で upsert。**再作成しない。消すのは `withdrawn` に書いた馬だけ** |
| 枠・馬番 | そのレースぶんをいったん NULL にしてから入れ直す（下記）             |
| 結果   | 書けば上書き、書かなければ既存を残す（`COALESCE`）                   |
| メモ   | **消さない。** 触るのは取り下げのときだけで、近況メモへ移す（上記「取り下げる」） |

### 馬の引き当てキー

上から順に試す。**同じ条件が「作る」「埋める」「出走馬に紐づける」の3箇所で使われる**ので、
引き当てた馬と更新する馬が食い違うことはない。

| 順 | 引き当て条件 | 効く場面 |
| --- | --- | --- |
| 1 | `external_ref` が `ref` と一致 | 2回目以降。同名馬がいても確実 |
| 2 | **まだ ref の付いていない**同名馬 | `ref` を後から足したとき |
| 3 | 同名かつ生年が一致 | `age` / `birthYear` を書いたとき |
| 4 | 同名かつ**生年が未設定** | `age` を後から足したとき |
| 5 | 同名のうち、生年未設定 → 生年が新しい順に1頭 | 名前だけで書いたとき |

**設計の肝は「後から足される」ことを前提にしていること。**
`ref` も生年も、名前だけで登録したあとに追記される。
追記のたびに新しい行ができてしまっては二段階で書ける意味がないので、
2 と 4 で「まだ埋まっていない行」を拾うようにしてある。

5 は同名の別世代がいると取り違えうる。確実にしたいなら `age` を書く。`ref` ならなお確実。

同じ `(name, birth_year)` の馬に**別の `ref` が既に付いている**場合だけは、
矛盾したデータなので `horse_name_birth` の UNIQUE に当たって落ちる。
どちらの `ref` が正しいかは機械には決められないので、これは落として正しい。

### 馬名を直す

**馬名の訂正はここから行う。画面には編集手段を置いていない**（→ [product.md 第9章 #13](../docs/product.md)）。

ただし**直せるのは `ref` を書いた馬だけ**。名前で引き当てている最中に名前を書き換えるのは
循環していて成立せず、引き当てが外れて別馬が1頭増えるだけになる。

```yaml
# ref が同じままなら、name を変えると既存の馬がリネームされる
- name: ニュージーランドトロフィー馬
  ref: nk-2022-01234
```

`ref` をまだ振っていない馬を直すには**2段階**になる。

1. 古い名前のまま `ref` だけ足す（既存の馬に ref が付く）
2. 次の PR で `name` を変える

1回で両方やると、ref も名前も一致しないので新しい馬ができてしまう。

同じ `ref` に別の名前を書いたファイルが混ざっていると、`data:check` が落ちる。
放置すると「最後に流したファイルが勝つ」になり、馬名が行ったり来たりするため。

```
✗ ref "sample-horse-a" に複数の馬名が付いています
    ホースA改  ← 2026-04-05.yaml
    ホースA    ← 2026-05-10.yaml, 2026-09-26.yaml
    ref は馬の同一性そのものなので、名前を揃えてください。
```

### 枠・馬番を入れ直す理由

レースごとに、まず `bracket` と `horse_number` を NULL に落としてから YAML の値を入れる。

確定後の訂正で2頭の馬番が入れ替わると、1頭ずつ更新する途中で
`entry_race_number` の UNIQUE `(race_id, horse_number)` に当たり、**実行ごと落ちる**。
先に外しておけば衝突しない。

その代わり、**YAML に載っていない出走馬の枠・馬番も NULL になる。**
そのレースの枠順については YAML が正、という割り切り。

出走馬を再作成しないのは、`race_entry` を消すと紐づくメモが
`ON DELETE CASCADE` で道連れになるため（docs/product.md 第10章）。
同じ理由で、消すのは `withdrawn` に書いた馬だけにし、消す前にメモを近況メモへ逃がす。

馬の属性は `COALESCE(<YAML の値>, <既存の値>)` で更新する。**結果欄と同じ挙動**で、
書けば上書き、書かなければ既存を残す。YAML に書かなかった項目が NULL で消えることはない。

転厩や馬名の変更（`ref` があるとき）が後から効くので、上書きできる側が正しい。
その代わり、**古い開催日のファイルに古い厩舎を書いて流し直すと、それが現在値になる。**
ファイルは名前順＝開催日順に処理されるので、同じ馬に複数のファイルが触れるときは
**いちばん新しい開催日のファイルが勝つ**。通常はこれで転厩が自然に反映される。

`profile_memo`（利用者が書くプロフィールメモ）には触れない。

## 注意

- **名前だけで書くと同名の別世代を取り違えうる。** 上の引き当てキーの 3 の場合。
  `age` を書けば解消する（出馬表の性齢を写すだけ）。それでも不安なら `ref`
- **YAML から行を消しても DB からは消えない。** 消すなら `withdrawn` に書く（上記「取り下げる」）。
  画面の「出走馬を編集」から消すと、紐づくメモも一緒に消えることに注意
- **ハッシュはファイル内容そのもの。** コメントを直しただけでも再投入の対象になる。
  投入は冪等なので実害はないが、`✓` が出ても中身が変わったとは限らない
- **SQL はトランザクションで包んでいない。** 途中で落ちれば部分適用になるが、
  `data_import` への記録は最後なので、次に流せば同じファイルがもう一度対象になる
