# Issue を Lead として進める

約束は `docs/orchestration.md` が正。このスキルは、その順番どおりに動くための入口で、約束は写さない。
最初に `docs/orchestration.md` を全部読む（第0章の承認と、第2章の Issue のコメントの読み方は毎回）。

## 始める前に確かめること

- 新しい Issue か、再開か。Issue のコメントに、自分の `gh` のアカウント（`gh api user --jq .login`）が書いたチェックポイントがあれば再開。第6章の順で状態を戻す
- Orca の Worker を使うなら、`orca-ide status` で Orca が動いていることを確かめ、`orca-ide skills get orchestration` を読む。
  Orca のコマンドは、そこに書いてある書き方だけを使う（覚えている書き方や推測で叩かない）

## 進め方

第3章の手順1〜9をそのまま進める。このスキルで足すのは、止まる場所の確認だけ。

| 手順           | 止まるか                                                       |
| -------------- | -------------------------------------------------------------- |
| 1 読む         | 受け入れ条件か対象外が無い・曖昧なら、書き足す案を出して止まる |
| 3 承認を受ける | **必ず止まる。** Task の表を示し、チャットで承認を受ける       |
| 5 待つ・答える | Worker の質問が第0章に当たれば、人に回して止まる               |
| 8 仕上げる     | PR を出したら止まる。マージは人が行う                          |
| 9 片付ける     | 消す worktree・ブランチとコマンドを示して止まる。消すのは人    |

各手順の節目（第3章「チェックポイント」）で、Issue にチェックポイントをコメントする。セッションを閉じる前も同じ。

## Worker に渡すとき

渡すものは第3章 手順2と第4章「受け取るもの」、並列の決め方は第0章と第5章、受け取ったあとは第3章 手順6・7。
