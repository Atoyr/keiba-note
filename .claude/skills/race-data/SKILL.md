# 出走馬データを入れる

`pnpm run data:fetch` で netkeiba から `data/races/<開催日>.yaml` を書き、`data:check` を通して PR を出す。
**書くのは YAML まで。** D1 には触らない。本番への投入は PR がマージされたときに GitHub Actions が行う。

最初に `data/README.md` の「三段階で書ける」「取り下げる」「取ってくる」を読む。書式と投入の性質はそこが正。

## 対象のレースを決める

コマンドはどれも `<開催日> <場> <R>` でレースを指す。YAML のキー `(date, course, raceNumber)` と同じ。

```bash
pnpm run data:fetch races 2026-09-27   # その日のレース一覧（場・R・race_id）
```

- **レース番号を決め打ちしない。** 重賞でも 11R とは限らない（ジャパンC は 12R、夏の暑熱対策の番組では CBC賞が 7R）。
  当週なら `races` の一覧で確かめる
- netkeiba の一覧は**当週ぶんしか出ない**。先の開催のレース番号は JRA の開催番組 PDF から取る。
  race_id が分かっていれば `--race-id` で渡せる
- `data/races/` に申し送り用の枠（`entries: []` のレース）が先に置いてあることがある。
  **同じレースに追記する**（開催日・場・R が同じなので、コマンドがそのレースを拾う）。
  追記するときにレース番号が番組と合っているかも見直す

## 手順

ふつうの1週間はこの順になる。どの手順も同じファイルを上書きしていくだけなので、何度流してもよい。

| いつ                   | すること                         | コマンド                      |
| ---------------------- | -------------------------------- | ----------------------------- |
| 特別登録の後（日〜水） | 候補を入れる → 過去走 → 基本情報 | `entries` → `past` → `horses` |
| 枠順確定（木・金）     | 枠・馬番を入れ、出ない候補を外す | `entries`                     |
| レース後               | 結果を入れる                     | `result`                      |

### 1. 候補を取る（枠が決まる前）

```bash
pnpm run data:fetch entries 2026-09-27 中山 11
```

- 出力の1行目が `枠順未確定: 登録馬 N頭を候補として入れます` になる。登録馬は18頭を超えてよい（40頭まで）
- 騎手が未定の馬は `jockey` を書かない。調教師・性齢・斤量・`ref`（`nk-<netkeiba の馬ID>`）は入る
- 前回から登録を外れた馬は `withdrawn` に移る（`- 馬名（出馬表に無いので withdrawn へ）`）

### 2. 枠・馬番を入れ、候補を取り下げる（枠順確定後）

```bash
pnpm run data:fetch entries 2026-09-27 中山 11
```

- 1行目が `枠順確定: N頭` になる。`entries` は馬番順に並び直る
- 出馬表に無い候補は **`entries` から外れて `withdrawn` に入る。** 投入すると DB の出走馬行が消える
- **取り下げた馬に付いていたメモは消えずに近況メモへ移る**（本文の先頭にレース名と印が書き足される）。
  PR 本文に取り下げた馬を並べて、そのことを書く
- 出馬表に戻ってきた馬は `↺ 取り下げから戻しました` と出て、`withdrawn` から外れる
- 取消・除外になった馬も、出馬表に馬番付きで載っている間は `entries` に残る（`result` を流しても着順は入らない）
- レースに `ref: nk-<race_id>` と `startTime: "HH:MM"`（発走時刻）が入る。**これがあるレースだけ、当日に
  予想画面へオッズが出る**（data/README.md「オッズを出すレース」）。最後の行に `ref … / 発走 15:40` と出る

確かめること: `entries` の頭数と馬番（1〜N の連番）が出馬表と合っている。`withdrawn` が想定した馬だけ。
レースの `startTime` が出馬表の発走時刻と合っている。

### 3. 過去5走を取る

```bash
pnpm run data:fetch past 2026-09-27 中山 11                 # 全頭
pnpm run data:fetch past 2026-09-27 中山 11 --horse ホースA  # 絞る（複数回書ける）
pnpm run data:fetch past 2026-09-27 中山 11 --count 3        # さかのぼる数を変える
```

- 対象は `ref` の付いた馬だけ。先に `entries` を流す
- 各馬の過去走を**それぞれの開催日のファイル**に足す。無いファイル・レースは作る
- JRA の10場のレースだけを数える（地方・海外は YAML に入らない）。取消・除外は数えない
- 既に書いてある値は書き換えない（空いている項目だけ埋める）。レース名も既存を残す
- 書き換えた過去のファイルは投入で流し直される。**そのレースの枠・馬番は YAML が正**なので、
  YAML に無い出走馬（画面から入れた馬）の枠・馬番は消える。PR 本文に書き換えたファイルを並べておく
- 着差は入らない（馬の戦績表は秒差で持っていて、競馬の表記と違う）。着差が要るなら、そのレースで `result` を流す
- 1秒に1回しか取りに行かないので、18頭でおよそ30秒かかる。`--interval 500` で0.5秒間隔まで縮められる

### 4. 馬の基本情報を更新する

```bash
pnpm run data:fetch horses 2026-09-27 中山 11
```

- 性・馬齢・調教師・父・母を**そのレースの行に上書きする**。転厩・セン化もこれで反映される
- 馬齢はそのレースの年で数える（生年はそこから `data:check` が導く）。年をまたいだ馬齢の更新も、
  新しいレースの行でこれを流せば済む
- 基本情報は**いちばん新しい開催日のファイルが勝つ**（data/README.md「枠・馬番を入れ直す理由」）ので、
  過去のファイルではなく、これから走るレースで流す

### 5. 結果を取る

```bash
pnpm run data:fetch result 2026-09-27 中山 11
```

- 着順・人気・タイム・着差・通過・上がり・斤量・馬体重・単勝オッズ・騎手・枠・馬番と、レースの馬場・天候を**上書きする**
- YAML にいる馬だけを更新する。気にしている馬だけ載せた条件戦に、他の馬は足さない（足さなかった馬は出力に並ぶ）
- 取消・除外・中止は着順が入らず、出力に `取消` などと出る
- 着順が数字で入った頭数が出走頭数と合っているかを見る

## 仕上げ

```bash
pnpm run data:check
git diff --stat
```

- `data:check` が落ちたら直す。よくあるもの:
  - `ref "…" に複数の馬名が付いています` — 馬名が過去のファイルと食い違っている。コマンドは馬名を書き換えないので、
    手で揃える（data/README.md「馬名を直す」）
  - `馬番 N が … と … で重複しています` — 同じレースに別の馬を同じ馬番で書いている
  - `… が entries と withdrawn の両方にいます` — 出走するなら `withdrawn` から外す
- `git diff` で、触るつもりのファイルだけが変わっているかを見る。既存の行の値が変わっていたら理由を確かめる
  （`result` は上書きなので、以前に手で入れた値と netkeiba が食い違うとそこが差分に出る。どちらが正しいかは
  db.netkeiba.com のレースページで確かめる）
- コミットは `data:` の接頭辞で、何を入れたか（例: `data: スプリンターズS の枠順を入れ、出走しない候補3頭を取り下げる`）
- **データの PR はコードの変更と混ぜない。** マージした時点で本番に入る
- PR 本文に書くこと:
  - **マージで本番に投入されること**（`data-import.yml`）
  - 入れたレースと手順（候補 / 枠順 / 過去走 / 基本情報 / 結果）
  - 取り下げた馬（付いていたメモは近況メモに移ること）
  - 「画面」欄には `data:check` の出力を貼る
- PR を出すところまで。マージと本番の D1 は人が扱う

## うまくいかないとき

- `… が netkeiba のレース一覧にありません` — 当週でない。race_id を調べて `--race-id` を付ける
- `出馬表に馬がいません` / `結果がまだ出ていません` — 登録・確定・レース前。時間をおいて流す。
  ページはあるのに0頭なら、netkeiba の HTML が変わっている。`scripts/race-data/netkeiba.ts` のパーサと
  `netkeiba.spec.ts` を直す（取ってきたページを作業用のディレクトリに保存して、どこが変わったかを見る）
- `! 馬名: netkeiba では「…」` — YAML の馬名と netkeiba が違う。打ち間違いなら data/README.md「馬名を直す」の手順で直す
- 試しに流したいときは `data/races/` をスクラッチにコピーして `--dir <そのディレクトリ>` を付ける

## やらないこと

- 本番の D1（`--remote`）への投入・`deploy`。人が行う
- `entries: []` に戻す。そのレースの枠・馬番が全部消える。外したい馬は `withdrawn` に書く
- YAML から行を消すだけで出走馬を消したつもりになる（DB からは消えない）
- netkeiba を必要以上に叩く。同じ手順を何度も回さず、`--horse` で絞る
