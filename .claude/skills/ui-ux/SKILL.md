# 画面の UI・UX を設計する

物差しは `docs/ux.md`、見た目の決まりは `docs/design-system.md`、画面ごとの仕様は `docs/pages.md` が正。
このスキルは、それを設計の順番に並べる入口で、物差しも決まりも写さない。
最初に `docs/ux.md` を全部読む（第0章の優先順と第3章の流行りの扱いは毎回）。

## 手順

AGENTS.md「作業の手順」の 1〜2（読む・before を撮る）のあと、実装に入る前に行う。

1. **読む。** 指示の原文、`docs/pages.md` の該当章、`docs/product.md` 1-2、`docs/harness.md` 1-3 の P1〜P7、
   `docs/design-system.md` の第4〜6章。今の画面は before のキャプチャと、その画面の `+page.svelte` と部品で見る
2. **場面を書く。** `docs/ux.md` 第1章の3つの場面のどれか。いつ・どの端末で・何と見比べながら使うか
3. **目的を1文にする。** その画面（変える部分）で何をし終えるか。主な情報と主な操作を1つずつ決める。
   1文にならなければ、分けるか畳む案を出す
4. **state を全部挙げる。** 下の表のうち当てはまるものに、それぞれ何を出すかを書く。「出さない」も書く
5. **置き方を決める。** 390px で最初の1画面に入るもの、畳むもの（`⋯`・折りたたみ・`InfoTip`）、主な操作の位置。
   PC の幅での並びも書く
6. **部品を選ぶ。** `docs/design-system.md` 第4章のドメイン部品 → 第3章の shadcn の部品 → 新しい部品の順に探す。
   新しい部品が要るなら、下の段で済まない理由を書く
7. **照らす。** `docs/ux.md` 第2章の表を上から読み、この変更に関係する物差しを挙げる。外す物差しがあれば理由を書く。
   流行りの見せ方を入れるなら第3章の扱いに従う
8. **書き出す。** 下の「設計に足す節」を `TASKS.md`（リポジトリ直下。コミットしない）の「設計」に足す。
   Claude Code で implementer に渡すときも、Lead として Worker に渡すときも、この節を設計に含めて渡す

| state                | 見ること                                                               |
| -------------------- | ---------------------------------------------------------------------- |
| ふつう               | 典型的な件数・長さで                                                   |
| 空                   | 0件（メモ・出走馬・結果）のとき、次に何をすればよいか                  |
| 多い・長い           | 18頭・長い馬名やレース名・長いメモで崩れないか、390px ではみ出さないか |
| 送信中               | 二重に押せないか、押したことが分かるか                                 |
| 失敗                 | 入力の誤り・保存の失敗・無いもの・他人のもの。文と、出す場所           |
| 済んだ               | 保存した・共有した、をどう知らせ、フォーカスがどこへ行くか             |
| 時間                 | 開催前・発走後・結果あり（`docs/pages.md` 1-4）                        |
| JS が無い            | フォームが送れるか、`<noscript>` で何を出すか                          |
| キーボード・読み上げ | Tab の順、名前、開け閉めと切り替えの伝え方（`docs/ux.md` 2-4）         |

## 設計に足す節

```markdown
### UI・UX

- 場面: <docs/ux.md 第1章のどれか。いつ・何と並べて>
- 目的: <この画面（部分）で何をし終えるか、1文>
- 主な情報 / 主な操作: <それぞれ1つ>
- 置き方: <390px の最初の1画面に入るもの・畳むもの・主な操作の位置。PC での並び>
- 部品: <使うドメイン部品・shadcn の部品。新しく作るならその理由>
- state: <上の表の当てはまるものごとに、何を出すか>
- 照らした物差し: <docs/ux.md の物差しの名前。外したものは理由>
- 決まりを変える案: <下の「決まりを変えたくなったとき」に当たるもの。無ければ「なし」>
```

この節は Generator の意図の解説なので、レビュアーと Evaluator には渡さない（`docs/evaluation.md` 第1章）。

## 決まりを変えたくなったとき

止まって人に聞くのは AGENTS.md「目指す状態」の条件のときだけ。このスキルで止まる条件は足さない。

`docs/product.md`・`docs/pages.md` で決めたことや、`docs/design-system.md` の決まり（第6章「避けること」を含む）を
変えたほうが良くなると考えたときも、**決まりの中で作れる案で進める。** 決まりを変える案は設計の「決まりを変える案」に書き、
PR 本文の「レビューで見てほしいところ」に、どの決まりをなぜ変えたいかと一緒に載せる。決めるのは人。

## 実装のあと

after のキャプチャは、設計に書いた state ごとに見る。画面カタログ（`e2e/screens.ts`）に無い state で見せたいものは1行足す。
できあがった画面の合否は自分で付けず、`docs/evaluation.md` に従って Evaluator に回す。
