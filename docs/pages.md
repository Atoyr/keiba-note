# uma-memo の画面ごとの仕様

画面ごとに何を出し、何を出さないか、なぜそうしたか。ふりかえり・予想・馬・重賞・騎手・共有の画面と、画面をまたぐ約束。

作成日: 2026-10-12 / 最終更新日: 2026-10-14

- **読む場面:** 画面の見せ方・出す条件・並びを足す・変えるとき。「この画面は何を出すはずか」を確かめるとき
- **ここに無いもの:** ルートの網羅と入出力は [api.md](./api.md)。表と列の意味は [data-model.md](./data-model.md)。
  何を作るか・やらないこと・認証と権限は [product.md](./product.md)。色・部品の選び方は [design-system.md](./design-system.md)。
  画面の書き方は [frontend.md](./frontend.md)。アルゴリズム（盤面の置き方、コース図の描き方）は、それぞれ `src/lib/utils/` の先頭コメントが正

## 1. 画面の地図と、画面をまたぐ約束

### 1-1. 画面の地図

ルートの網羅（メソッド・入力・失敗）は [api.md 第3章](./api.md)。ここは画面の役割だけを並べる。

```
── 公開（ログイン不要） ──────────────────────────────────
/notes/[id]                   ★共有ページ（メモ1件）。unlisted のメモだけを出す
/shared/races/[id]            ★共有ページ（予想まとめ）。本人が作った共有用コピーを出す
/login                        ログイン（[Googleでログイン] のみ）
/（未ログイン）                紹介ページ。データは出さない。Google の同意画面のホームページ
/privacy・/terms              プライバシーポリシー・利用規約（Google の同意画面に登録する）

── 要ログイン ────────────────────────────────────────────
/                             ダッシュボード（自分の最近のメモ / 今週のレース / 過去のレース / 推しの出走予定）
/this-week                    今週の重賞（予想の入口）
/races                        レース一覧（既定は今年の重賞）
/races/[id]                   ★ふりかえり＝レースを見終わったあとに書く
/races/[id]/preview           ★予想＝出馬表 + 馬柱 + 予想印。開催前に書く
/races/[id]/summary           予想まとめ（本人の閲覧と共有の操作）
/horses・/horses/[id]         馬一覧／★馬詳細＝プロフィール + タイムライン
/graded-races・/graded-races/[name]   重賞一覧／★重賞＝傾向のメモ + 年ごとの予想とふりかえり
/jockeys・/jockeys/[name]     騎手一覧／★騎手＝自分のメモ + 騎乗のタイムライン
/settings/profile・shares・connections   公開名／共有中の一覧（取り消す場所）／AI との連携（解除する場所）
/oauth/authorize              AI のアプリへの同意画面
/help/mcp・/help/webmcp       AI との連携・WebMCP の使い方

── admin のみ ────────────────────────────────────────────
/races/new                    レース登録
/races/[id]/entries           出走馬の一括入力・編集
/settings/admin               ユーザー一覧・凍結・AI の利用量のリセット・出走馬の取得の依頼
```

**まだ無いもの:** レース情報の編集画面（`/races/[id]/edit`）、馬の登録画面（`/horses/new`）、マスタ（レース・馬）の削除。
直すときは出走馬データ（YAML）を再投入する。馬のプロフィールは `/horses/[id]` の中で admin が直す（馬名は含まない。→ [product.md 第4章](./product.md) #13）。

### 1-2. ヘッダ

右端はアバター1つ（アカウントメニュー）にまとめる。プロフィール・共有中・管理・ログアウトはその中に畳む。
出しっぱなしにするのは毎回踏む導線（今週・レース・重賞・馬・騎手）だけ。

### 1-3. レースが行で並ぶ一覧の並び

**格の札（`GradeBadge`）をレース名の前に置く。** 名前だけではどの格の重賞か分からないので、名前を読む前に格が目に入るようにする。
ダッシュボードのレース欄・最近のメモの見出し・今週の重賞・レース一覧・馬柱のすべてでそろえ、**一覧ごとにずらさない**
（縦に並んだ行を目で追うとき、札の位置が一覧ごとに変わると目が迷う）。

- 条件戦のクラス（`1勝クラス` など）を札の代わりに出す一覧（レース一覧・馬柱）では、クラスも同じ位置に置く。`grade` が NULL のレースには何も付けない
- 札の前の「中山11R」は `RacePlace` で幅をそろえる。成り行きの幅だと「福島1R」と「中山11R」で札の左右の位置が行ごとに動き、縦に追えない
- 最近のメモの見出しも、格は「(G2)」の文字ではなく札で出す（`noteHeadingParts`）。レースの行と同じ画面で書き方が違うと、同じ格が別のものに見える
- 1レースを開いた画面の見出し（ふりかえり・予想の `RaceHeading`）と共有ページは並ぶ行ではないので、この決まりの外に置く。
  見出しは1行目に場・R・レース名、2行目に格の札・日付・条件（距離・回り・頭数）を置く（予想・ふりかえり・予想まとめ・共有ページとも同じ。→ 4）。ふりかえりだけは3行目に「馬場：良 / 天候：曇」を出す（馬場状態・天候は当日まで決まらないので、予想・予想まとめ・共有では出さない。片方だけなら片方だけ、どちらも無ければ3行目ごと出さない）。1行目の右端の発走時刻は予想・ふりかえりだけに出す。開催・時刻・メニューを縮めず長いタイトルだけを省略する。条件の行は省略せず、幅が足りなければ折り返す

### 1-4. 開催前か、結果が出たか

画面ごとにずらさない。判定は `src/lib/utils/date.ts`。

- **開催前** — `isUpcoming(date, today)`（`date > today`）。**当日は開催前にしない。** 朝は開催前でも、走り終えた夕方には開催前ではなく、
  日付だけでは決められないので、その日のうちはふりかえりを書けるようにする。馬のタイムラインの「出走予定」、重賞・騎手の画面の「開催予定」も同じ線引き
- **ふりかえり画面を開けるか** — 日付（`isUpcoming`）だけで決める。結果の投入が遅れた日でも、予想画面の「ふりかえりを書く」から入って書けるように
- **一覧からのリンク先** — 結果が出ているか（`isSettled`。開催済みで、着順の入った出走が1頭以上）。当日の朝に見立てを書こうと開いたレースがふりかえりへ飛ぶと、書きたい画面に着かない。
  着順が入ったらふりかえりへ向ける。今週の重賞・ダッシュボード・レース一覧・馬のタイムライン・重賞・騎手の画面のすべてでそろえる
- **自分がふりかえりを書いてあるレース**は、結果の投入前でもふりかえりへ向ける（`opensReview`）。予想画面にふりかえりは出ないので、押して書いたものが無い画面に着くことになるため
- 「今週」の範囲は月曜〜日曜（JST）で、連休は最終日まで（→ [product.md 第4章](./product.md) #15）

### 1-5. 性齢

馬の性と馬齢を1つの札（`牡4`・`牝5`・`セ7`。`SexAgeBadge`／馬詳細の頭）で出す。性で色を分ける（色は [design-system.md](./design-system.md)）。

- **馬齢は JRA の数え方（毎年1月1日に加齢）で、年 − 生年。** 生年月日の月日は使わない
- 馬詳細の頭は「今の年 − 生年」。ふりかえり画面と予想画面の出走馬の行、馬のタイムラインのレースの行（`4歳`）は**そのレースの日付の年 − 生年**で、過去のレースを開けばそのときの馬齢になる
- **性は馬のいまの値**（`horse.sex`）で、レース当時の値ではない。あとでセン馬になった馬は、過去のレースでも `セ` と出る
- 性だけなら `牡`、馬齢だけなら `4歳`、どちらも無ければ何も出さない。生年が無い馬と、近況メモの行にはレース当時の馬齢を出さない

### 1-6. 長い一覧 — `/races` と `/horses`

**100件ずつ読み、下端に近づいたら次の100件を足す。** 全件を1回で返すと、開催を重ねるほど最初の表示が遅くなる。
かといって件数で切ると、古いレースや名前の後ろの馬に一覧からたどり着けなくなる。

- 続きは下端の少し手前で読み始める。読み終えても下端がまだ近ければ続けて読む。下端に「続きを読み込む」も置く（キーボードの人と、自動で読めなかったときの入口）
- **読んでも URL は変えない。** リロードや共有で開くと1ページ目から出る。一覧の場所を覚えておく画面ではないので、変えると戻る・共有のたびに途中から始まってかえって迷う
- 一覧から1つ開いて**戻ると、読んだ行とスクロール位置が残る**。戻るたびに先頭から読み直させない
- 読めなかったら自動では読み直さない。下端に文を出し、「もう一度読み込む」を押してもらう
- 絞り込みを変えたら、読み足した行は捨てて新しい条件の1ページ目から出す
- JavaScript が無ければ「続きを読み込む」は `?offset=100` のページへのリンクとして働き、そのページに「先頭から見る」を出す
- 実装の書き方は [frontend.md 3-2](./frontend.md)

## 2. 探す画面 — `/`・`/this-week`・`/races`・`/horses`

### 2-1. `/` — ダッシュボード

レースは **「今週のレース」と「過去のレース」の2枠**に分けて出す。

```
┌──────────────────────────────────────────────┐
│ ■ 今週のレース  9/21(月) 〜 9/27(日)  [＋登録]│
│ 2026-09-26 中山11R G2 オールカマー   メモ 0  │
│ 2026-09-27 阪神11R G2 神戸新聞杯     メモ 3  │
├──────────────────────────────────────────────┤
│ ■ 過去のレース  直近3週                      │
│ 2026-09-20 中山11R G3 ○○S           メモ 2  │
│ 2026-09-13 中京11R △△特別           メモ 0  │
└──────────────────────────────────────────────┘
```

**1本の一覧で日付順に並べると、この画面が使えなくなる。** 重賞は開催のずっと前に枠だけ登録する（→ [data/README.md](../data/README.md)）ので、先の予定が上を埋めて今週の開催が見えない。
ここで知りたいのは2つ、「これから書くレース（今週）」と「書いたか確かめたいレース（終わったばかり）」で、間にある先の予定はどちらでもない。

- **今週** — `/this-week` と同じ範囲（`resolveWeek`）。画面ごとに週の切り方が違うと、同じレースが今週に出たり出なかったりする。日付の昇順
- **過去** — 今週の**前**の3週間（`weeksBefore`）。週の頭で切るので、日曜に見ても月曜に見ても中身が変わらない。日付の降順（最後に走ったレースから）
- どちらも重賞に絞らない。`/this-week` は予想の入口なので JRA・芝・重賞だけだが、ダッシュボードは自分が書く場所の目次なので、条件戦が落ちると歯抜けに見える
- 3週より古いレースはここには出ない。探すのは `/races`。「すべてのレースを見る」は一覧の既定（今年の重賞）ではなく全件（`/races?year=`）へ向ける
- 各行に進み具合の札を添える。「メモ 3」では何が済んで何が残っているか読めないため。結果が出る前は見立てと印（候補の ✓ は数えない。4-3）、出たあとはふりかえりが済んだか。
  予想したのに結果のあとに何も書いていないレースを「ふりかえり待ち」として集める。境目は日付でなく `isSettled`（リンク先と同じ線引き。
  「ふりかえり待ち」と出ているのに押すと予想画面へ行く食い違いを作らないため）。予想していない開催後のレースには何も添えない（全部が宿題に見えるため）。ロジックは `utils/dashboard.ts`
- 「今週出走する注目馬」は、今週の出走のうち、自分のメモに結論の札（`次走買い`・`次走消し`）が付いた馬を並べる。同じ出走は**いちばん新しい結論だけ**を採る（見限った馬がいつまでも出続けないため）

### 2-2. `/` — 推しの出走予定

馬の画面（`/horses/[id]`）で星のボタンを押して推しにした馬の、**まだ走り終えていない出走**を早い順に並べる。注目馬のすぐ下に置く。

- **今週に限らない。** 推しを追う理由は「次どこに出るか」なので、先に登録した重賞（枠だけ先に入れる → [data/README.md](../data/README.md)）まで出す
- 当日のレースは、結果が入るまでは予定に残す（`isSettled`）。日付だけで切ると、朝に開いたとき今日の出走が出ない
- 行は「日付・馬名・レース（格の札はレース名の前）・馬番」。馬番は枠順が出てから。レースのリンク先は他の一覧と同じ（`opensReview`）
- 出走予定の無い推しは、下に名前だけ並べる。出さないと、推しにした馬が画面のどこにも見えなくなる
- 推しがまだいなければ、どこで推しにするかを案内する（枠ごと消さない。この機能があることを知る場所になる）
- 通知はしない（[product.md 第1章](./product.md)「やらないこと」のまま）

### 2-3. `/this-week` — 今週の重賞

予想の入口。今週（連休は最終日まで）の JRA・芝・重賞を日付ごとに並べ、`?w=` で前後の週へ動かせる。リンク先は予想画面で、結果が出たレースだけふりかえりへ向ける（→ 1-4）。

### 2-4. `/races` — レース一覧

年度・ランク（G1〜OP の OR）・レース名（部分一致）で絞る。条件は GET のクエリで、そのまま URL に残る（`utils/race-filter.ts`）。

**何も指定せずに開くと、今年の重賞（G1〜G3）に絞る。** 一覧は日付降順なので、絞らないと条件戦と、枠だけ先に登録した先の重賞が上を埋める。
探しに来るのはほとんどが今年の重賞なので、そこから始める。L・OP は重賞ではないので既定には入れない。

- 既定になるのは、`year` `grade` `q` の**どれも URL に無いとき**だけ。フォームは年度を必ず送るので、「すべて」を選んでランクを外して送れば全件になる。どれか1つでも付いていれば、ほかを既定で補わない
- 「条件をクリア」は既定ではなく**全件**（`/races?year=`）へ。既定に戻すと、クリアしても絞られたままに見える
- 既定の状態もフォームにそのまま映す（年度に今年、G1〜G3 にチェック）。何で絞られているかは見れば分かる
- 今年のレースがまだ1つも無くても、年度の選択肢に今年を入れる（無いと「すべて」を選んだように見える）
- 既定のまま0件のときは「条件に合うレースがありません」と言わない。本人は条件を付けていないので、「今年の重賞はまだありません」と、全件へのリンクを出す（admin には登録の案内も）
- 件数（「N 件」）は読み込んだ行の数ではなく、条件に当たる**全体の数**を出す（100件ずつ読むので → 1-6）

### 2-5. `/horses` — 馬一覧

名前の部分一致で絞る。100件ずつ読む（→ 1-6）。

## 3. ふりかえり — `/races/[id]`

このアプリで一番よく使う画面。**1画面・1送信でレース1本分のふりかえりが完結する**ことを目標にする。

**まだ走っていないレースでは開けない。** 開催前にこの画面を開くと予想画面（`/races/[id]/preview`）へ 302 で送る。走る前に「どう走ったか」を訊く欄が出ていると、書く場所を間違えたのかと読ませてしまう。
**入口ごとに塞ぐのではなく、この画面自身が行き先を持つ。** ダッシュボードもレース一覧も馬タイムラインも開催前のレースを普通に並べるので、どこか1つを直し忘れた時点で穴が開く。
一覧側でリンク先を分けてあるのは1回余計に往復しないためで、正しさを担保しているのはこの画面の振り分けのほう（線引きは 1-4）。

初期表示は「ふりかえり」タブ。答え合わせ・実際の展開・ラップ、開催前の見立てとレースのメモを入力側に置く。
毎年共通の重賞の傾向・重賞のタイムライン・同じ条件で書いたレースのメモ・コース図は「レース情報」に集約する（→ 4-6）。基本情報は見出しに載せる（→ 4）。

各馬の行は畳まない。見出し（枠・馬番、性齢、馬名、騎手、着順と予想印）と走りの数字に続けて、畳んだ「詳細情報（メモ・直近5走）」（→ 4-2）、出走前のメモ、ふりかえりのメモを置く。
出走前のメモ（保存済み。本文か札があるとき。印だけなら見出しの印で足りるので出さない）は**読むだけ**で、種別の札（出走前）・本文（3行まで）・メモの札で出す。直すのは予想画面。
ふりかえりのメモは**押すとその場で書ける**（→ 4-3）。メモがあれば、種別の札（ふりかえり）・本文（3行まで）・メモの札を、保存前を含む**いま入力している値**から出す（古い保存済みの値が出ると書いたものが消えたように見える）。無ければ「＋ ふりかえりメモ」を出す。
状態の文言（「メモを入力する」など）は出さない。馬・騎手のメモは詳細情報の中にある（18頭ぶんを常に出すと縦に伸びるため）。
新しい評価項目は足さず、予想をふりかえり保存で上書きしない。

- 開催前に書いた見立て（`race_preview`）があれば、レースのメモの上に**読み取り専用**で出す。ここから直せるようにすると「結果を見たあとで見立てを書き換える」ができてしまい、
  事前と事後を別の行にした意味が無くなる。直すのは予想画面
- 各馬の行の馬名の左に性齢の札（→ 1-5）。騎手名は騎手の画面へのリンクで、自分の騎手のメモがあれば開ける（→ 7）
- 各馬の行見出しの直下（**詳細情報を開かなくても見える位置**）に、**走りを読むための数字**を1行で出す。着順順の一覧で走りを見比べるため。詳細情報の中には重ねて出さない。着順と上りのタイムだけでは「前で粘ったのか、後ろから届いたのか」「上りが速かったのか」が読めず、ふりかえりが着順の書き写しになる。
  どれも結果（`race_entry`）にもう入っている値から出す（計算は `utils/run-stats.ts`）
  - **4角の位置 → 着順**（`4角12番手→3着`）。直線のレース（新潟の芝1000m）と、競走中止で通過順が途中で切れた馬には出さない（最後の数字が4角ではないため）
  - **上りの順位**。上位3頭だけ順位を添えた札にし、1位は黄・2位は水色・3位は橙で塗る（人が選んだ）。4位以下は順位を出さない（18頭ぶん数字が並ぶと埋もれる）。
    **走った全頭の上りがそろっているときだけ**数える。出走馬は気にしている馬だけ入れてよいので、入っている馬の中で数えると、1頭だけのレースで6着の馬が「上り1位」になる
  - **人気**（確定の人気。予想画面の単勝オッズから付ける人気とは別の値）
  - どれも無い馬（取消・結果の投入前）には行を出さない
- 答え合わせの下に**実際の展開**（`ActualFlow`）を出す。4コーナーとゴール前の隊列を、予想と同じ盤面（`RaceFlowBoard`）と隊列の1行（`②-①③-④`）で出す。
  **展開を予想していなくても出す。** どう流れたかは結果から読めるので、予想の有無で消えると、展開を考えなかったレースほど材料が減る
  - 既定は畳む（予想の「展開の予想」と同じ形。人が選んだ）。閉じた行には局面ごとの隊列の1行を出す。盤面2枚を開いたままにすると、スマホで書く欄が遠くなる
  - 4角は通過順、ゴール前は着差（読めなければ着順）で置く。ハナ差の2頭と2馬身離れた2頭が同じ見た目にならないよう、着差が読めるときは着差で置く（人が選んだ）。置き方の詳細は `utils/run-stats.ts` の `actualFlow`
  - **結果には内外が無い。** 盤面の上下は内外でないことを見出しに書き、読み上げは段でなく順位にする
  - 予想で展開を置いていたら、開いた中の盤面の下の1行に予想の隊列を並べる（「実際」「予想」の札）。予想の盤面は「開催前の見立て」を開いて見る。見立ての閉じた行には、重なる局面（4角・ゴール前）の隊列を出さない（スタートは出す）
  - **走った全頭がそろっているレースだけ**出す。気にしている馬だけ入れたレースで並べると、2頭の並びが全体の流れのように読める。4角は、完走した全馬が4角の位置を持つときだけ（直線のレースはゴール前だけ）
- 実際の展開の下に**ラップ**（`RaceLaps`）を出す。「レースのメモ」に書くペースを、感じたことではなく数字で確かめるため
  - 既定は畳む。閉じた行に前半3F・後半3Fと差（「後半が1.4秒速い」）、予想の展開でペースを選んでいればそれも並べる（答え合わせ）
  - 開くと区間タイムの折れ線と、区間タイムの1行（表の代わり）。**速い区間ほど上**に描き（ペースが上がったところが山に見える）、縦の目盛りは 0 秒から取らない（区間の差は 1〜2 秒で、0 からだと線が平らになる）
  - 前半3F・後半3Fの数え方（最初の区間が端数のときは飛ばす）は `utils/laps.ts`。レース全体の値なので、出走馬がそろっていないレースでも出す。ラップの入っていないレースには出さない
- コース図（→ 4-5）はレース情報の末尾に置く。スマホでは図を畳む
- 全馬分のテキストエリアを1つの `<form>` に入れ、1回の form action で保存する。本文も札も空の馬はスキップ（メモを作らない）。**既存メモがあれば消える**＝これが削除操作
- 既存メモがあればそこに表示され、編集＝上書き。保存は D1 の `batch()` で1往復にまとめる

### 3-1. 書き忘れと、書いたものが消えること

この2つは別の問題で、原因も対策も違う。混ぜて考えると的を外す。

| 問題 | 原因 | 対策 |
| --- | --- | --- |
| 書き忘れ | 保存していないことに気づけない | 未保存のときだけ出る保存ボタン（件数つき）＋離脱時の確認 |
| 書いたものが消える | 離脱・リロード・**電波が悪くて保存が失敗** | `localStorage` の下書き |

- **保存の単位は一括のまま。** 1頭ごとにサーバーへ送る案もあるが、競馬場で電波が悪いと18回のうち何回かが黙って失敗し、どれが落ちたか分からなくなる。
  一括なら「1回成功したか」だけ見れば済む。**オフラインで守れるのは端末内の下書きだけ**で、1頭ごとのサーバー保存はそこを守らない
- **保存ボタンは未保存の変更があるときだけ出す。** いつも出ていると、書いたものが保存済みかを画面から読めない。ボタンが出ていること自体を「保存していないものがある」の合図にする
- **件数の1件はメモ1つ**（レースのメモ、または1頭ぶん）。保存の知らせの「（N 件）」も同じ数え方で、**その保存で変えたメモの数**を出す。
  押す前の「未保存の変更が N 件」と数が変わると、何か操作を間違えたのかと読ませてしまう
- **下書きの復元は明示操作**（「復元する」を押す）にする。自動で流し込むと「空欄＝削除」と噛み合って、既存メモが黙って消える事故になる
- **下書きを消すのは保存が通ったときだけ。** 失敗したら残す（電波が悪くて落ちた場合に書いたものを失わない）。入れるのは**サーバーの値から変えた項目だけ**
- 下書きは保険であって本体ではない。`localStorage` が使えなくても入力は続けられる
- 実装の書き方（`SaveBar`・`DraftKeeper`・離脱時の確認・`update({ reset: false })`）は [frontend.md 第3章](./frontend.md)。
  保存した直後に中身が消えたように見えた状態でもう一度保存すると、「空欄＝そのメモを消す」仕様なので**本当に消える**

## 4. 予想 — `/races/[id]/preview`

出馬表の形で、各馬に**馬柱**と**自分の過去メモ**を並べる。ふりかえりが結果を見て書く場なのに対して、こちらは**結果を見る前に書く場**。開催前に書けるのはこの画面だけ。

書けるのは2つ。**レース全体の見立て**（`race_preview`）と、1頭ごとの出走前メモ（`preview`）。

見出しはふりかえりと同じ形にする（ふりかえりだけが持つ馬場状態・天候の3行目を除く）。1行目は場・R・レース名で、右端に発走時刻（「15:45発走」。`⋯` の左。時刻が入っていないレースでは出さない）。
2行目は格の札・日付・条件（距離・回り・頭数）で、格の札は日付の前に置く。組み立ては `utils/race-heading.ts` を共有する。予想の時点では馬場状態・天候が決まらないので、ここには出さない（ふりかえりだけが3行目に出す）。基本情報（開催日・場・R・発走・格／クラス・距離・回り・頭数）はここに載せ、レース情報タブには表を出さない。
頭数は予想・ふりかえりとも、登録行数から作らず取得元の `race.fieldSize` があるときだけ条件の末尾に足す（不明なら出さない）。

**ほかの画面への導線は、見出しの右端の `⋯` に畳む**（ふりかえり画面も同じ）。項目は「予想をまとめて見る」「重賞のタイムライン」（G1〜G3 で名前のあるレースだけ）、
予想画面では「ふりかえりを書く」（開催前は出さない）、ふりかえり画面では「予想（過去メモを見る）」、admin には「出走馬を編集」。
どれも毎回は踏まない導線で、書く欄より先に目に入る必要が無いため。
**レース名（見出しの1行目）を押しても同じメニューが開く。** 重賞に限らず全レースで同じにする（押せるかどうかがレースで変わると分かりにくい）。
JS が無いときはメニューが開かないので、見出しの下にボタンの行を出す。

初期表示は「予想」タブ。付けた印は印順（◎ → ×）に1頭1行で並べ、押すとその馬の行へ飛ぶ。候補の ✓ は予想の印ではないので並べない（4-3）。
レースの見立て・展開の予想・出馬表と各馬の入力をメイン側に置く。コースや長い資料は「レース情報」に集約する（→ 4-6）。

### 4-1. レースの見立てと展開の予想

**見立ては出走馬が1頭もいなくても書ける。** これから組まれる重賞は日付と格だけ先に登録され、出馬表はその後に入る（→ [data/README.md](../data/README.md)）。
この段階が「このレースを狙う」と思いつく時期そのものなので、書き留める先が要る。出走馬が0頭のときは保存ボタンも「レースの見立てを保存」と名乗る
（書くものが1つしかないのに「出走前メモを保存」と言うと、画面に出ていない何かも保存されるように読める）。

見出しをふりかえりの「レースのメモ」と別の名前（「レースの見立て」）にしてあるのは、**同じ名前だと同じ欄に見える**ため。実際には別の行で、どちらを保存してももう片方は消えない。

**見立ての下に「展開の予想」を畳んで置く**（出走馬がいるときだけ。盤面に置く馬がいないため）。見続けるものではないので既定は閉じ、閉じた行にペースと隊列の1行
（`スタート ⑤-③⑦ → 4角 … → ゴール前 …`）だけを出す。開くとペース・局面のタブ（スタート／4コーナー／ゴール前）・盤面・まだ置いていない馬・一言メモが出る。

- **置き方はタップだけ。** 馬を押して選び、置くマスを押す。置いたコマを選んで別のマスを押すと動き、別の馬のマスなら入れ替わる。スマホでドラッグに頼らない
- 盤面は上が内ラチで、**先頭はスタンドから見た向き**（右回りは左、左回りは右）。中継の画面と同じ向きにして、頭の中の絵と取り違えないようにする。
  回りが入っていないレースは場の回り（コース図と同じ出どころ）で決め、直線コースと場も分からないレースは先頭を左にする
- 4角・ゴール前は「前の局面の並びを写す」から始められる（スタートの並びを少し動かすことが多い）
- コマは枠の色に馬番。馬番が無いうちは馬名の頭2文字。コマの先頭側の縁に小さな三角を付け、進む向きを指す（置いている最中に盤面を見ても向きを取り違えやすいため）
- 保存は「まとめて保存」に乗り、下書きにも入る
- キーボードでは盤面が1つの止まり場所で、矢印キーでマスを移る（40マスを Tab で辿らせない）
- 予想まとめ・共有ページ・ふりかえりの「開催前の見立て」でも**畳んで出す**。閉じた行はペースと隊列の1行で、開くと3局面の盤面が並ぶ。
  開いたまま置くと、スマホでは盤面が 700px を超えて各馬の印を1画面目から押し出す（ここからは直せない）

### 4-2. 馬柱

各馬の行の見出しの下・印とメモの入力の上に、畳んだ「詳細情報（メモ・直近5走）」を置く。中は馬のメモ・騎手のメモ（→ 4-3）に続けて直近5走。初期は閉じ、開いた馬の資料だけを表示する。
全体の詳細・過去メモトグルは設けない。0走なら「過去走の記録がありません。」、1〜4走なら存在する分だけを出す。

- 登録済みの出走のうち対象レースより前の日付から新しい順に最大5走。着順未入力の走も落とさない
- 日付・レース名・格／クラス・開催場・馬場と距離・馬場状態、着順・人気・上がり3Fを表示する
- 頭数・枠番と馬番・騎手、勝ち馬（勝った走は2着馬）とタイム差、走破タイム・通過順位を近接させる。頭数は `race.fieldSize` で、登録行数で補完しない
- 欠損は「—」または項目省略。過去走の上がり順位や脚質を、不完全な母数から推測しない
- 直近5走は列をそろえた表（日付・レース / 着順 / 枠番 / 通過 / 上り / 人気。補足は各走の2段目）にし、その下に、各走の出走IDに紐付く本人の出走前・ふりかえりメモを走ごとに種別付きで出す（印・本文・札）。読むだけとし、既存のレース画面へ確認・編集に行く
- 詳細情報から他の画面へ飛べる。各走の騎手名は騎手の画面（`/jockeys/[name]`。騎手のメモの Popover は出さず、点線の下線のリンク）へ、G1〜G3 でレース名のある走のレース名は重賞の画面（`/graded-races/[name]`）へ。条件戦・L・OP のレース名は文字のまま
- 近況メモを特定の走りに結び付けない。現在のレースの予想や他人の共有中／非公開メモは混ぜない
- 過去走は馬ごとの窓関数、各走メモは出走IDの IN でまとめて取得する。馬・過去走ごとの N+1 は増やさない

結果は出馬表と同じ [data/races/](../data/races/) の YAML に追記する（→ [data/README.md](../data/README.md)）。

### 4-3. 出走馬の行

- 行は畳まない。見出しで枠・馬番、性齢、馬名、騎手、人気・オッズ、予想印を、その下のメモ（本文・札）で比較する。並びは **見出し → 詳細情報（畳む）→ 印 → 出走前メモ**（ふりかえり画面は 見出し → 走りの数字 → 詳細情報 → 出走前メモ（読むだけ）→ ふりかえりメモ。印は予想の読むだけで、見出しにある）
- 枠番と馬番は `HorseNumberBadge`。スマホではその下に性齢を置く。馬・騎手のリンクはメモの操作と独立させる
- 出走馬は1頭ずつのカードにせず、**1枚の枠に区切り線で行を並べる**（予想・ふりかえりとも）。予想画面の◎の赤い枠は、区切り線の一覧では枠線が使えないので、内側の赤い輪で出す。詳細情報の中は、馬のメモ・騎手のメモ・直近5走をそれぞれ薄い面にする。印とメモの入力欄は行の中なので面を付けない
- 見出しの印・◎の赤い枠と、一覧の上の「付けた印」は、保存済みの値ではなく**いま選んでいる印**（保存前を含む）から出す。印は常に出ていて、行を開かずに選べる。選ぶと保存するまで見出しが古いままにならない
- 印のボタンは**正方形で左寄せ**。PC（`sm` 以上）は 40px 四方、**スマホは 36px 四方**にして、390px でも7つの印と「なし」の8枚を1行に収める（40px だと「なし」だけが2行目に回り、出走馬の行が毎行のびる。36px でも指で押せる大きさは保てる）。「なし」も同じ大きさ。それでも幅が足りなければ折り返す。読み上げの名前は「{馬名}の予想印」
- **✓（候補）を ☆ と × の間に置く。** 印を付けている途中で「この馬は気になる」と残しておくためのチェックで、**予想の印ではない**。付ける場所と保存はほかの印と同じ（1頭に付くのは印か候補のどちらか1つ）だが、予想をまとめる・数える場所では**印なしと同じ**に扱う: 一覧の上の「付けた印」・予想まとめと共有のコピー（✓ だけで本文も札も無い馬は行ごと出さない）・ふりかえりの答え合わせ（◎○▲△☆ の「馬券内」に数えない）・重賞の年ごとの印・ダッシュボードの進み具合の「印 N頭」。各馬の見出し・馬柱の各走・馬と騎手の画面のメモは1頭ごとの作業の跡なので ✓ も出す（teal の札。title は「候補」）。読み上げは「チェックマーク」だけでは意味が伝わらないので「候補」と添える
- メモ（本文・札）も同じく、**いま入力している値**から出す（保存前を含む。下書きの復元・AI の反映も入る）。本文か札があれば、本文を3行までと札をそのまま出し（種別の札を付ける。予想画面は「出走前」（無いと、すぐ上の「前回」の札の続きに読める）。ふりかえり画面は出走前（読むだけ）とふりかえりを札付きで並べる。→ 3）、**そのメモの表示がそのままボタン**（右端に ⌄）になっていて、押すとその場で入力欄（本文・札）が開く。メモが無ければ「＋ 出走前メモ」（ふりかえり画面は「＋ ふりかえりメモ」）のボタン（同じく右端に ⌄）を出す。状態の文言（「メモを入力する」「過去のメモあり」など）は出さない
- 入力欄が開くと、ボタンはその場で見出し「{label} ⌃」（「出走前メモ ⌃」「ふりかえりメモ ⌃」）になり、本文の欄にフォーカスが移る。書いている間は書いたメモの表示を出さない（入力欄と同じものが2つ並ぶため）。見出しを押す（か Esc）と折りたたまれて、書いたメモの表示（か「＋ {label}」）に戻る。ボタンは同じ要素なので、フォーカスはそのボタンに残る（Esc のときはそのボタンへ戻す）。保存が通ったら、開いている入力欄はすべて閉じて、書いたメモの表示に戻す（保存できたことが見て分かる）。別のレースへ移っても閉じる
- 馬のメモ（近況の要点は最新2件・前回の札）→ 騎手のメモ（本人の本文・札1件）→ 直近5走の順に、畳んだ詳細情報の中へ置く。前回の札は見出し、騎手のメモは騎手名の枠で読めるので、日常の比較は畳んだままで足りる
- メモが無ければ空の大きな枠を作らない。馬・騎手の全文や編集は既存画面への導線を出す
- 馬のメモの近況は、**そのレースの日以前に書いた**最新2件。レースの後に書いた近況は出さない。直近5走の各走メモと近況に出ていないメモ（5走より前の出走メモ・レース後の近況など）があれば、件数と馬の画面への入口（「ほかに N 件のメモ。馬の画面で全文・編集を見る」）を出す
- メモのボタンの名前は、馬名（読み上げ専用）と見えている文字（メモの表示、または「＋ 出走前メモ」）を続けたもの（メモの表示のほうは「{馬名}の出走前メモを書き直す。」を頭に付ける。ふりかえり画面は「＋ ふりかえりメモ」「{馬名}のふりかえりメモを書き直す。」）。開け閉めのボタンは1つで、`aria-expanded` と `aria-controls`（入力欄）を持つ。開いたときの名前は「{馬名}の{label}」で、開いているかは `aria-expanded` が伝える
- 書く・折りたたむは保存・破棄ではない。別の馬、詳細、タブ、並び順を操作しても全馬の未保存入力を保持する
- **入力欄は書いていない間も DOM に残す**（`hidden`）。非表示タブも同じで、一括フォームに全入力を含める。未保存件数、離脱確認、下書きの明示復元、保存失敗時の保持は 3-1 のまま
- メモのボタンは JS で開くので、hydration が済むまでは押せない形（disabled）で出す。押しても何も起きない時間を、押せるように見せない。
  JS が無いときは、開け閉めのボタンを隠し、入力欄を出しっぱなしにする（`<noscript>` の style）。資料の詳細情報はネイティブの `details` なので JS無効時も開ける。保存は同じ HTML フォームで行う

### 4-4. オッズと人気

**オッズは各馬の見出しの右端（印の左）に、人気・単勝（`nnn.n`）を1段目、複勝（`nn.n - nn.n`）を2段目に出し、一覧の上に取れた時点を1行添える**（「単勝・複勝のオッズは 9/27 14:30時点」）。

- 出すのは GitHub Actions が D1 に置いた値だけ。この画面から取得元へは行かない（→ [product.md 第1章](./product.md)）
- **時点を必ず出す。** 30分おきにしか取らず、失敗した回は前の値が残る。「現在」「リアルタイム」とは書かない。日付も付けるのは、前日の値が残っているときに今日の値と取り違えないため
- 値の無い馬（取消・馬番未定）は `-`。前売りの始まった直後に複勝が片側しか出ていない馬は、複勝だけ `-`。1度も取れていないレース（`ref` か発走時刻が無い、発売前）では、オッズの欄ごと出さない
- 見出しは2段の表にする（前回の札があるときだけ3段）。1段目は「枠・馬番の札／馬名／人気／単勝／印」、2段目は「性齢の札／騎手／複勝」（複勝は人気と単勝の下に渡す）、3段目は前回の札。スマホも PC も同じ形
- **馬名と騎手は折り返さない。** スマホ（390px）でも全角9文字の馬名が切れずに入る幅を残し、入らない幅では … で切る
- 人気・単勝・複勝はそれぞれ幅を固定して右に寄せ、**印の場所は印が無くても取っておく。** どの馬でもオッズが同じ位置に来て、縦に見比べられる
- 見える「単勝」「複勝」の文字は出さない（スマホの1段目に置く幅が無い）。1つの数が単勝・幅が複勝で、一覧の上の時点の行が「単勝・複勝のオッズは」と添える。読み上げには文字で残す

**人気は単勝オッズの低い順に付けて、単勝の左に出す**（「1人気　3.4」）。

- 取得元の人気は票数で決まるが、持っているのはオッズだけなので、オッズで順を付ける。同じオッズは同じ人気にし、次はその頭数ぶん飛ばす（1 / 2 / 2 / 4）
- オッズの無い馬（取消）には付けない。人気の欄の幅は空けたままにして、単勝・複勝の位置をそろえる
- **出走馬は「馬番順」と「人気順」を切り替えて並べられる**（オッズが取れているときだけ、時点の行の右に出す）。既定は馬番順。人気の無い馬は人気順の後ろに回す
- 切り替えは画面の中だけで行い、URL は変えない。書きかけのメモがあっても並べ替えで離脱の確認を出さないため。JS が無いときは切り替えを出さない（馬番順のまま）

### 4-5. コース図

そのレースの馬場（芝・ダート・新潟の直線）を色で、ほかのコースを薄い灰色で描き、回り・直線の長さ・高低差を文字で添える（色だけに頼らない）。
ふりかえり画面にも同じ図を置く。JRA の10場以外と、馬場が決まっていないレースには出さない。

- 寸法は JRA の「コース紹介」の A コースの値。図は形と大きさの見当をつけるための模式図で、**JRA のコース図は写さない**（著作物）。全場で同じ縮尺にしてあり、東京と札幌の大きさの違いが図でも分かる
- **内回り・外回りのある場（新潟・中山・京都・阪神）は距離で出し分ける。** どちらか一方にだけ載っている距離はそのコースだけを強く描く。決められない距離は両方を描いて寸法も両方出す。
  どの距離がどちらか、決められない距離はどれかは `utils/course.ts` の `loopDistances`
- **レースの距離で、スタートからゴールまで走る道すじを黄色い線で重ねる。** 線はその馬場の帯の中央を通り、スタートの端に丸を置く。1周を超える距離は2周目に入り、線は重なる。
  距離を出せないレース（距離が分からない・障害・内回り外回りが決まらない芝・直線コースの長さを超える距離）には出さない。引き方は `utils/course.ts` の `courseRoute`
- **図の下に、スタートからゴールまでの高低断面を出す。** 坂の位置（中山のゴール前の急坂、京都の3コーナーの坂）は図より断面のほうが読み取りやすいので、坂はこちらで見せる。
  高さの目盛りは全場で同じにする（レースごとに合わせると、札幌の 0.7m も中山の 5.3m と同じ山に見える）。ゴールの向きはスタンドから見た向き。
  数値は JRA の高低断面図を読み取った概数で、図そのものは写さない（`utils/course-elevation.ts`・`course-elevation-data.ts`）。内回り・外回りが決まらない距離、障害、距離の入っていないレースには出さない

### 4-6. レース情報タブ

予想・ふりかえりだけに設ける資料タブ。初期は入力側で、タブ変更による URL 移動や保存はしない。
本人の毎年共通の重賞の傾向 → 重賞のタイムライン（どちらも重賞のとき）→ 同じ条件で書いたレースのメモ → コース図の順に並べる。メインは傾向・重賞のタイムライン・同じ条件のメモで、コース図は末尾に置く。

- 基本情報の表は置かない。画面の見出しに載っている（馬場状態・天候は当日まで決まらないので、ふりかえりの見出しだけに出す。→ 4）
- 過去成績（総称。そういう名前の欄は無い）は、重賞のタイムラインと同じ条件で書いたレースのメモで見せる。新しい集計は作らない
- **重賞のタイムライン**（G1〜G3 で名前のあるレースだけ）は、重賞の画面の年ごとのメモ（→ 6）と同じ行（`GradedRaceTimeline`）を、ほかの年について出す。
  見出しの右の「重賞の画面で見る」から重賞の画面へ行く。傾向が無くても出す
  - **このレース自身の行は出さない。** このレースの見立て・ふりかえりは入力側にあり、保存済みの値をタブに出すと入力中の値と食い違って見える
  - ほかの年のレースが1つも登録されていなければ「ほかの年のこのレースは、まだ登録されていません。」
- 同じ条件で書いたレースのメモからは、重賞のタイムラインに出したレースのメモを除く（同じふりかえりを2回並べない）。除くのは問い合わせの中で（5件に切る前）。重賞のレースで0件なら「ほかに同じ条件で書いたレースのメモはありません。」、重賞でないレースで0件なら「同じ条件のレースメモはまだありません。」
- 毎年共通の重賞の傾向と年ごとのレースメモを分ける。傾向の編集先は重賞画面（→ 6）
- 資料を入力タブへ重複表示しない。レースの見立て・展開予想・ふりかえりのレースメモは入力側に残す
- タブは名前・選択状態・対象を読み上げられる。左右・Home・Endキーで選び、Tabで内容へ進む
- タブの並びはサーバーが描く（hydration で出すと一覧が下へずれる）。JS が無いときは押しても切り替わらないので隠し、両方の内容を続けて出す


## 5. 馬 — `/horses/[id]`

```
┌──────────────────────────────────────────────┐
│ 2021年4月4日生                               │
│ [牡6] ホースA                              ★ │
│ [父 サンプル]                                │
│ [母 ○○] [母父 ○○]                           │
│ [栗東] [調教師 ○○]                           │
│ [プロフィールメモ]                           │
├──────────────────────────────────────────────┤
│ ■ タイムライン          [+ 近況メモを追加]   │
│                                              │
│ 2026-10-25  [出走予定] 東京11R 天皇賞(秋)    │← メモはまだ無い
│                                              │
│ 2026-09-20  中山11R オールカマー(G2) 1着     │
│   直線で外に出してから一完歩が速い。         │
│   [次走買い][好上がり]                       │
│                                              │
│ 2026-08-16  [出走] 新潟10R ○○特別 5着      │← 何も書かなかった走り
│                                              │

```

頭（`HorseProfileHeader`）は、名前の上に生年月日（`2021年4月4日生`。生年だけなら `2021年生`）の行を左寄せで置く。
名前の行は左に性齢の札（→ 1-5）、馬名、右端に推しの★。その下に父、母と母父、所属（美浦・栗東など）と調教師の札の行。★のほかは左寄せで、折り返しても左から詰まる。値の無い項目は出さない。

レース紐付きメモと近況メモが同じ流れに並ぶ。これが `note` を1つの表にした狙い（→ [data-model.md 3-1](./data-model.md)）。

**並びは未来 → 過去。** 次走が先頭に来て、古い走りほど下に沈む。馬を追う理由は「次どこに出るか」なので、開くたびに下までたどるのは筋が悪い。

**骨はメモではなく出走（`race_entry`）。** メモを書いた日だけを並べると、走ったのに何も書かなかったレースがタイムラインから消え、
「間隔が空いた」のか「書き忘れた」のかが読めなくなる。そこで出走を先に並べ、そこにメモを重ねる。

- メモのある出走は**メモの行だけ**出す（レース名も着順もメモ行が持っている）。突き合わせは `race_entry_id`。
  1走に出走前メモとふりかえりメモの2件が付くことがあるので、1件でもあれば出走だけの行は出さない
- 出走は全ユーザー共通のマスタなので、**誰が見ても同じ**。メモだけが viewer で絞られる
- まだ日が来ていない出走は `[出走予定]` として着順を出さない（線引きは 1-4）。レースの行には**そのレース当時の馬齢**を添える（→ 1-5）
- 馬名の右に星のボタン（文字なし）。推しなら黄色く塗った★、そうでなければ黄色の輪郭だけの☆。押すと推しにする／推しから外す（名前は読み上げと hover で出す）。
  押したボタンが次の状態を送る（二重に押しても行き来しない）。推しは本人だけのもので、マスタの馬には何も書かないので、admin でなくても押せる。推しの出走予定はダッシュボードに出る（→ 2-2）

## 6. 重賞 — `/graded-races/[name]`

「この重賞は毎年どんなレースになってきたか」を、年ごとの自分の予想とふりかえりから見返す画面。ヘッダの「重賞」の一覧から開く。
予想画面・ふりかえり画面の見出しのメニュー（`⋯`）の「重賞のタイムライン」（G1〜G3 のレースだけ）と、レース情報タブの重賞のタイムラインの「重賞の画面で見る」からも開ける。年ごとの行はレース情報タブにも出る（このレース自身の行を除く。→ 4-6）。

```
┌──────────────────────────────────────────────┐
│ オールカマー                                 │
│ [G2] 格は2026年のもの  9/27(日) 中山 芝2200m │
├──────────────────────────────────────────────┤
│ ■ 傾向                                       │
│   内枠の先行馬が残る年が多い。               │
│                                    書き直す │
├──────────────────────────────────────────────┤
│ ■ 年ごとのメモ                               │
│ 2026年                                       │
│ 2026-09-27 [開催予定] 中山11R オールカマー   │
│   芝2200m                                    │
│   [予想] ペース スロー                       │
│   内枠の先行馬が残る。                       │
│   ◎ ⑤ ホースA  ▲ ③ ホースB                  │
│ 2025年                                       │
│ 2025-09-28 中山11R 産経賞オールカマー        │
│   芝2200m・良  勝ち馬 ホースA                │
│   [予想] … ◎ ⑤ ホースA 1着                   │

│ 2024年                                       │
│ 2024-09-22 中山11R オールカマー  メモはありません│
└──────────────────────────────────────────────┘
```

- **重賞は「レース名」で束ねる。ただしコードの別名表で寄せる**（`utils/graded-race.ts`。理由は [data-model.md](./data-model.md) の `graded_race_note`）。
  寄せた名前（＝重賞の鍵）が URL と傾向のメモの鍵になる。表に無い名前はそのまま鍵になる
- **一覧（`/graded-races`）に出すのは、今年（JST の暦年）に G1〜G3 で登録されているレース。格は今年のもの。**
  過去の年のレースは、その年の格に関わらず鍵が同じなら同じ重賞として並べる（G3 から G2 に上がった重賞も1本の流れ）。年ごとの行には格を出さない（見出しの格＝今年の格だけ）。芝に絞らない（ダート・障害の重賞も入る）
- 画面の見出しの格は今年のレースの格。今年のレースがまだ登録されていなければ、いちばん新しい年の格を出し、「YYYY年の格（今年のレースは未登録）」と添える。
  今年のレースは登録されているが G1〜G3 でない（格が下がった）ときも、いちばん新しい重賞の年の格を出し、「YYYY年の格（今年は重賞ではありません）」と添える
  （一覧には出ないが、URL と過去の年のレースの導線からは開ける）。鍵に当たるレースが1つも G1〜G3 でなければ 404（`2歳新馬` などを重賞として開かせない）。
  既定のエラー画面にせず、一覧へ戻る道を出す（`+error.svelte`）
- **年ごとに出すのは、レース全体の見立て（`race_preview`。ペースがあれば出す）・ふりかえりのレースのメモ（`race`。札つき）と、付けた印。**
  1頭ごとの出走前メモ・ふりかえりメモの本文は出さない（18頭 × 年数で傾向が読めなくなる。読むときはレースを開く）。
  代わりに、その年のレースに1頭ごとのメモ（出走前は印の有無を問わない・ふりかえり）があれば「1頭ごとのメモ N件」を補足色で出し、レースへのリンクにする（行き先は年の行と同じ）。
  「メモはありません」は、見立て・ふりかえり・印・1頭ごとのメモのどれも無いときだけ。印は印の順（◎ ○ ▲ △ ☆ ×。候補の ✓ は出さない）、同じ印は馬番の昇順に「◎ ⑤ ホースA 1着」の形で並べる。予想の答え合わせが年ごとに並ぶと傾向になる
- 年は降順（新しい年が上）。メモの無い年も破線で並べる。レースへのリンクは結果の有無で振り分ける（1-4）
- **傾向のメモは1人・1重賞につき1本（本文だけ。札は無い）。** 騎手のメモと同じ形で、空で保存すると消える。札を作らないのは、傾向の言葉が重賞ごとに違い、固定の選択肢を作れないため。
  本人だけのもので、マスタには何も書かないので、admin でなくても書ける。傾向のメモは鍵と別名すべての行から読む（別名の表に行を足して鍵が変わっても、古い鍵で書いた傾向が消えない）。保存すると鍵の行に寄り、別名の行は消える
- 一覧の行は、日付・格・名前・場所と距離を並べ、右にメモのある年の数（`メモ N年`。見立て・ふりかえり・1頭ごとのメモのどれかを書いた年）と、傾向を書いていれば「傾向」の札を出す

### 6-1. 予想画面・ふりかえり画面に出る「重賞の傾向」

**重賞なら、自分の傾向のメモを、予想・ふりかえり両方のレース情報タブに、読むだけで出す。** 年ごとのレースの見立て・ふりかえりとは別の毎年共通のメモ。配置は 4-6。

- 出すのは G1〜G3 で名前のあるレースだけ。**傾向を書いていなくても枠を出し**、「まだ傾向のメモはありません。」と「重賞の画面で書く」を出す（人が選んだ。重賞ごとのメモがあることと、書く場所を見せるため）
- 見出しは「重賞の傾向」で、後ろに「{重賞の名前}・毎年共通」を添え、このレースのメモではなく重賞ごとの毎年共通のメモだと分かるようにする。重賞の名前は別名の表で寄せた鍵（別名で走った年のレースでも、重賞の画面の名前が出る）
- 枠は重賞の画面の傾向の枠と同じ白地（空色は結果を見る前の見立ての色なので使わない）。枠の中の「重賞の画面で直す」（無ければ「重賞の画面で書く」）から重賞の画面へ行く。直すのはこの画面だけ
- 他人の傾向は出ない。共有ページ・予想まとめ（`/races/[id]/summary`）には出さない

## 7. 騎手 — `/jockeys/[name]`

予想のときに「この騎手はどう乗ってきたか」を、騎乗と自分のメモから見返す画面。予想画面・ふりかえり画面の騎手名から開ける（ヘッダの「騎手」から一覧で探すこともできる）。

```
┌──────────────────────────────────────────────┐
│ ルメール                                     │
│ 騎乗 207 回（このアプリに入っている出走のうち）│
├──────────────────────────────────────────────┤
│ ■ 騎手のメモ ⓘ                               │
│   中山の内回りは前に行く。                   │
│   [中山巧者][先行が多い]            書き直す │
├──────────────────────────────────────────────┤
│ ■ 騎乗          [すべて 207][メモのある騎乗 12]│
│ 2026-10-25 [出走予定] 東京11R 天皇賞(秋) (G1)│
│   ⑤ ホースA                                  │
│ 2026-09-20 中山11R オールカマー (G2)         │
│   ③ ホースB  1着  2人気                      │
│   [出走前] ◎ 内枠を活かしたい。              │
│   直線で外に出してから一完歩が速い。         │
│   [次走買い]                                 │
│ 2026-08-16 新潟10R ○○特別 (3勝クラス)       │← 何も書かなかった騎乗
│   ⑧ ホースC  5着                             │
└──────────────────────────────────────────────┘
```

- **騎手のメモは1人・1騎手につき1つだけ**（本文と札）。騎乗ごとのメモは書かない。騎乗のことは馬のメモ（出走前・ふりかえり）に書いてあるので、それをこの画面に集める
- 画面の言葉は「騎手のメモ」（見出し・騎手名の枠。書く・保存のボタンは「メモ」）。騎乗の下に並ぶ馬のメモと読み分けるため、一覧の件数は「騎乗のメモ」と呼ぶ。
  コードと表では `summary`・`jockey_note`、コメントと api.md・data-model.md では「まとめ」と呼ぶ（コードの上で馬のメモと取り違えないため）
- 見出しの info アイコン（`InfoTip`）で、このメモがどこに出るかを1文で出す。本文と札は予想・ふりかえりの画面の騎手名の枠と出走馬の詳細情報、札はほかに騎手名の隣（→ 7-1）と騎手の一覧
- **骨は騎乗（`race_entry`）で、メモは騎乗の下に重ねる。** 馬のタイムラインと違い、メモの行が騎乗の行の代わりにならない（「どの馬で」が要るので）。
  出すメモはその騎乗に付いた自分の出走前メモ（`preview`。薄い面に載せ、印も出す）とふりかえり（`entry`）だけ。
  馬の近況メモ（`horse`）は騎乗に付かないので出さない。同じ馬でも別の騎手が乗った走りのメモは出さない
- 並びは未来 → 過去。次の騎乗が先頭（線引きは 1-4）。メモの無い騎乗も並べる（破線）。数百になるので、「メモのある騎乗」だけに絞れる（`?notes=1`。URL に残る）。新しい300騎乗まで出す
- **勝率のような数は出さない。** 入っている出走は重賞の出走馬と気にしている馬の過去走だけで、騎手の全成績ではない。偏った母数の率は、予想の材料として誤って読まれる
- 騎手のメモは本人だけのもので、マスタには何も書かないので、admin でなくても書ける
- 騎乗の無い名前は 404。騎手は名前で束ねているので、表記が変わると前のリンクが古くなる。既定のエラー画面にせず、騎手の一覧へ戻る道を出す（`+error.svelte`）

`/jockeys`（一覧）は騎乗の多い順に、騎乗数・最後の騎乗日・騎乗に付けた自分のメモ（出走前・ふりかえり）の数（「騎乗のメモ N 件」）・自分の札を並べる。名前の部分一致と、自分が付けた札で絞れる
（札の選択肢は**自分が使っている札だけ**。付けていない札で絞っても0件になるだけなので）。予想するレースの場の「〇〇巧者」を付けた騎手を引くのが札の使い道。
騎乗の多い200人まで出し、それを超えたら名前で探すよう断る。

### 7-1. 予想画面・ふりかえり画面の騎手名

出走馬の行の騎手名の決まり。詳細情報（直近5走）の騎手名は騎手の画面へのただのリンクで、騎手のメモの枠は開かない（→ 4-2）。

- 点線の下線を常に出す（スマホには hover が無く、灰色の文字だけではリンクと分からない）
- 自分の騎手のメモがあれば、名前の右に notebook-pen のアイコンを出す（hover しなくても、メモの有無が一覧でひと目で分かる）。狭い幅では名前だけを省略し、アイコンは残す
- 押す（クリック・タップ）と、自分の騎手のメモ（本文・札）を小さな枠（`Popover`）で開く。マウスでもタッチでも同じ。**hover では開かない**（じっくり読むもので、hover だと読んでいる途中で消えるため）。
  本文は全文を出し、長ければ枠の中でスクロールする。枠の中の「騎手の画面へ」から騎手の画面へ行く。外を押す・Esc で閉じる。
  開くので、騎手名はリンクでなくボタンになる（hydration 前と、メモの無い騎手はリンクのまま）。出すのは自分のメモだけで、他人のメモは出ない。メモの無い騎手は何も出さない（空の枠も「まだありません」も出さない）
- 騎手名の隣に、このレースに合う札だけを出す（開かなくても見える）。レースの場の「〇〇巧者」（東京のレースなら東京巧者。中山巧者は出さない）と、芝のレースなら芝巧者・ダートならダート巧者。
  距離・道悪・乗り方・狙いどころの札は、レースの条件だけでは合うか決められないので出さない（騎手の画面と、開いた枠には全部出る）

## 8. 共有 — `/notes/[id]`・`/shared/races/[id]`

メモは人に見せる前提で書くものではないので、既定は非公開（→ [product.md 第2章](./product.md)）。見せたくなったものだけ、本人が明示して共有する。共有には2種類ある。

| | 単体メモ | 予想まとめ |
| --- | --- | --- |
| 公開ページ | `/notes/[id]` | `/shared/races/[id]` |
| 公開するもの | `visibility = 'unlisted'` にしたメモ1件 | 共有した時点の予想のコピー（`race_share`）。元のメモの `visibility` は変えない |
| 取り消し | `private` に戻す。**再共有すると同じ URL** | コピーを削除する。**再共有は新しい URL**（取り消した URL は復活しない） |
| 取り消す場所 | `/settings/shares` | `/settings/shares` |

どちらも**ログイン不要**で、著者が開いても第三者が開いても同じページになる（渡す前に自分で踏んで見え方を確かめられる）。

### 8-1. `/notes/[id]` — 単体メモ

```
┌──────────────────────────────────────────────┐
│ 2026-09-20  中山11R オールカマー(G2)         │
│ ホースA  1着                                 │
│                                              │
│ 直線で外に出してから一完歩が速い。           │
│ [次走買い][好上がり]                         │
│                                              │
│ — 週末うまメモ                               │
└──────────────────────────────────────────────┘
```

- ヒットしなければ **404**。`private` でも「存在しない」でも同じ 404 にする。403 を返すと「その ID のメモは在る」ことを教えてしまう。自分のメモでも `private` なら 404
- 出すもの: メモ本文、札／印、日付、文脈（レース名・日付・馬名・着順）、著者が設定した公開用の名前（未設定は「匿名」）。
  **出さないもの:** アプリ内へのリンク、同じ著者の他のメモ、前後のメモへの導線、一覧への戻り。1件で閉じていること自体が「検索で辿り着けない」を支えている

**検索に載せない。** 要件の「検索することはできない」は、サイト内とサイト外の両方を指す。

- サイト内: 他人のメモを返すクエリが存在しない（→ [data-model.md](./data-model.md) の主要クエリ）
- 検索エンジン・Referer・共有キャッシュ: 共有ページの応答に `noindex`・`no-referrer`・`no-store` を付ける（[architecture.md 3-7](./architecture.md)）
- **`robots.txt` で `/notes/` を Disallow してはいけない。** クロールを止めるとクローラは `noindex` を読めず、外部からリンクされた URL が「内容なしの URL だけ」の形でインデックスされうる。
  狙いはクロールの拒否ではなくインデックスの拒否なので、**crawl は許して noindex を読ませる**。正は `static/robots.txt`

**URL の推測不能性。** ID は ULID（48ビットのタイムスタンプ + **80ビットの乱数**）。乱数部だけで 2^80 あり、総当たりは成立しない。共有トークンを別に持つ必要はない。
ただし**単体メモは `private` に戻してから再共有しても URL が同じ**になる。一度渡した URL を持っている相手は、再共有した瞬間にまた見られる。
取り消しを「渡した相手から確実に取り上げる」ことにしたくなったら、`share_token` 列を足して再共有のたびに振り直す（→ [product.md 第4章](./product.md) #11）。今はやらない。

### 8-2. 共有の操作をどこに置くか

**保存フォームからは公開範囲の入力を外す。** 保存は常に `private` で入る。ふりかえり画面で18頭分のチェックボックスを並べても、既定が非公開である以上ほぼ誰も触らず、「うっかり公開」の事故だけが残る。
共有は書いたあとの別の操作にする。

- 表示済みの各メモに `[共有リンクを作る]` — 押すと `unlisted` になり、URL とコピーボタンが出る
- 共有中のメモには `[共有をやめる]`（`private` に戻す）と「共有中」バッジ。既定が非公開なので、目印を付けるのは**例外のほう**（「共有中」を出し、`private` には何も出さない）
- `/settings/shares` に共有中のメモと予想まとめを一覧し、取り消せる

### 8-3. 予想まとめ — `/races/[id]/summary` と `/shared/races/[id]`

- `/races/[id]/summary` は本人だけの閲覧画面。予想画面とふりかえり画面から開ける。
  レース全体の見立て（展開の予想を含む）と、予想を保存した馬の本文・札・印を、印順（◎ → ○ → ▲ → △ → ☆ → × → 印なし）、同じ印は馬番の昇順にまとめる。候補の ✓ は印なしとして扱い、✓ だけで本文も札も無い馬は出さない。
  共有済みのページも表示時に同じ順序へ揃える。馬番未確定は同じ印の最後に置く。ふりかえりや過去メモ、他人の予想は含めない。印なしのメモも表示し、印だけ・見立てだけでも使える。
  「予想まとめ」と同じ行の右端に「予想」とシェアアイコンを置く。「予想」で入力画面へ戻る
- シェアアイコンは共有リンクを作成・更新して端末の投稿先選択（Web Share API）を開く。非対応端末ではリンクをコピーし、コピー不可ならリンク欄を案内する。共有画面を閉じてもリンクは有効。
  通信待ちで投稿先選択を開けなかった場合は、発行済みリンクで「投稿先を選ぶ」を再試行できる
- 「共有リンクを作る」で共有用コピーを保存し、`/shared/races/[id]` を発行する。あとからの編集・削除を自動で公開せず、シェアアイコンか「共有内容を更新」で同じ URL に反映する。現在の予想とコピーが違う場合は更新の案内を出す
- `/settings/profile` で公開用の名前を設定する。前後の空白を除去し30文字以内、空欄なら匿名。Google の名前・メール・画像を共有ページの表示にもデータにも含めない。公開名の変更は既存の単体メモ・予想まとめにも反映する
- 共有リンクを SNS に貼ると、プレビューに**予想の印**が出る（OGP）。X は説明文を出さず画像だけを大きく出すので、印は画像（1200×630）に描く。
  画像はレース（開催・レース名・格・条件）、印を付けた馬（印・枠と馬番・馬名。まとめと同じ印順、10頭を超えたら9頭と「ほか n 頭」）、公開名。印が1つも無ければレースの見立ての頭を描く。
  説明文（LINE・Discord などが出す）は「公開名 の予想｜◎1 馬名 ○5 馬名 …」。どちらも共有のコピーと公開名だけから作る。
  「共有内容を更新」したときと公開名を変えたときは画像の URL も変わる（前の名前の画像を使い回させない）が、SNS 側が前のプレビューを持っている間は、前の画像が出ることがある。項目名と組み立ては [api.md 第3章](./api.md)
- **ログインしていない人にだけ、ページの一番下に uma-memo の案内を出す。** 「ログインして始める」（`/login`）と「できることを見る」（紹介ページ `/`）の2つ。
  予想まとめは SNS に流れて初めて見る人の目に入るので、そこから使い始められる入口を置く。まとめ本体は誰が開いても同じで、違うのはこの案内の有無だけ。
  渡すのはログインしているかの真偽だけで、アカウント情報は送らない。単体メモの共有ページ（`/notes/[id]`）には出さない（1件で閉じる決めごとのまま）
- 検索抑止・キャッシュ抑止は単体メモ共有と同じ。見つからない・取り消し済み・著者凍結済みは 404
