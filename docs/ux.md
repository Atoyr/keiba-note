# uma-memo の UI・UX の物差し

画面の構成・導線・状態を決めるときに、決まりが書かれていないところをどう判断するか。
Laws of UX・Nielsen の10の原則・GOV.UK Design System・Inclusive Components・Apple HIG から、このアプリに当てはまるものを選んで書き直した。

- 作成日: 2026-10-26 / 最終更新日: 2026-10-26
- **読む場面:** 画面を足す・操作や表示を足す・置き場所や導線を変える・空やエラーの state を決めるとき。
  手順は `ui-ux` スキル（`.claude/skills/ui-ux/`）が入口
- **ここに無いもの:** 色・部品・余白・文言の決まりは [design-system.md](./design-system.md)、
  Svelte とフォームの書き方は [frontend.md](./frontend.md)、画面ごとの仕様は [pages.md](./pages.md)、
  プロダクトの原則 P1〜P7（草案）は [harness.md 1-3](./harness.md)、
  できあがった画面の評価の観点は [evaluation.md 第3章](./evaluation.md)

## 0. この文書の位置

**決まりがあるところでは決まりが勝つ。** ぶつかったときは上が勝つ。

1. [product.md](./product.md)・[pages.md](./pages.md) で決めたこと（何を・誰に見せるか）
2. [design-system.md](./design-system.md)・[frontend.md](./frontend.md) の決まり（どう作るか）
3. [harness.md 1-3](./harness.md) の P1〜P7
4. この文書の物差し
5. 外のガイドの一般論と、流行りの見せ方

この文書は 4 にあたる。上の決まりを変えたほうがよいと考えたら、ここで上書きせず、決まりの中で作れる案で進め、
その文書を変える案を PR 本文の「レビューで見てほしいところ」に書く（`ui-ux` スキル「決まりを変えたくなったとき」）。
外のガイドを読んで直に当てはめないのは、ガイドごとに前提（大きな組織の手続き画面、ネイティブアプリ）が違い、
同じ「良い UI」でも結論が食い違うから。

## 1. 使う人と場面

uma-memo を使うのは、自分のメモを自分で読み書きする1人（[product.md 1-1](./product.md)）。他人に見せるのは共有のリンクだけ。
場面は次の3つで、求められるものが違う。

| 場面 | いつ・何と並べて | 画面に求められること |
| --- | --- | --- |
| 予想を書く | 結果を見る前。馬柱・オッズを横に見ながら（[product.md 1-2](./product.md)） | 書くのに要る情報が同じ画面にある。発走が迫っても迷わず書ける |
| ふりかえりを書く | レースを見終わったあと、覚えているうちに。中継や新聞と見比べながら | 全頭を1画面で書ける（P1）。書きかけを失わない（P6）。外の世界と同じ色・記号 |
| 読み返す | 後日。馬・重賞・騎手を追いかけて | 時系列と比較が一目で分かる。探す手数が少ない |

書く場面では**速さと失わないこと**、読む場面では**一覧性と比べやすさ**を優先する。
どちらもスマホで使う（P5）ので、390px で最初の1画面に何が入るかで並びを決める。

## 2. 判断の物差し

各表の「出典」は第4章の略号。

### 2-1. 何を・どの順で見せるか

| 物差し | uma-memo でどうするか | 出典 |
| --- | --- | --- |
| **1画面の目的は1つ** | 画面ごとに「この画面で何をし終えるか」を1文で言えるようにする。言えない画面は分けるか、目的でない部分を畳む。ふりかえりの全頭1画面（P1）は「1レースをふりかえる」で1つ | GOV.UK（One thing per page）、HIG（Hierarchy） |
| **作るものを減らす** | 足す前に、今ある画面・部品・操作で済まないかを見る。足さずに済む案があれば、それを先に出す | GOV.UK（Do less） |
| **選択肢を減らす** | 一度に見せる選択肢が多いほど選ぶのが遅くなる。毎回は使わない操作は `⋯` に畳む（P4）。選ぶ数が多い入力は系統で段に分ける（`JockeyTagPicker`） | Hick の法則 |
| **かたまりで見せる** | 出走馬の行のように情報が多いものは、意味のかたまり（枠と馬番・馬名・騎手・メモ）に分け、かたまりの中を近くに・かたまりの間を空ける | Miller の法則、近接・共通領域 |
| **大事なものを上・左に** | 主な情報と主な操作を最初の1画面の上か左に置く。強調は色でなく太さと置き場所でつける（[design-system.md 第6章](./design-system.md)） | 系列位置効果、HIG（Hierarchy） |
| **目立たせるのは1画面に1つ** | 塗ったボタン（`Button` の既定）は1画面・1かたまりに1つにする。2つあるとどちらも目立たない | Von Restorff 効果 |
| **知っているやり方に合わせる** | 競馬新聞・中継・ほかの Web サービスで通じている並びと記号（枠色、◎○▲△、馬柱の並び、`⋯` のメニュー）に合わせる。新しいやり方を発明しない | Jakob の法則、Nielsen #2・#4 |
| **複雑さはアプリが持つ** | 開催前か後か、どの入口かは日時と状態からアプリが決める（P3）。人に選ばせない。既定値で済むものは既定値を入れる | Tesler の法則 |
| **思い出させず、見せる** | 書くのに要る情報（馬柱・オッズ・前走のメモ）を、別の画面へ見に行かせずに同じ画面に出す。畳むなら、開け閉めはその場で | Nielsen #6 |

### 2-2. 操作

| 物差し | uma-memo でどうするか | 出典 |
| --- | --- | --- |
| **押しやすい大きさと場所** | 押せるものの大きさは [design-system.md 第5章](./design-system.md)。よく押すものほど大きく、親指の届く画面の下半分か行の端に置く。消す操作は主な操作のすぐ隣に置かない | Fitts の法則、HIG（Layout） |
| **誤りは起きる前に防ぐ** | 防ぐ順は「選べないようにする（その時に要らない操作を出さない、選択肢で入れさせる）」→「取り消せるようにする」→「確かめる」。確かめる文は何が起きるかを先に書く | Nielsen #5・#3 |
| **取り消せる・戻れる** | 書きかけは `DraftKeeper` で残す（P6）。画面を離れて戻ったときに残したい状態は、今ある持ち方に倣う（絞り込みは URL のクエリ、読んだ一覧は `snapshot`、馬柱の表示は `localStorage`） | Nielsen #3 |
| **入力は寛容に受ける** | 全角数字や前後の空白のような、意味の変わらない揺れは受けて直す。保存して出す形は1つに揃える | Postel の法則 |
| **応答は速く、遅いなら知らせる** | 送るフォームには、速く返ると見込めても、押したことが分かる表示（送信中の `pending`）と二重送信の防止を必ず付ける。0.4 秒を超えると待たされていると感じ始めるが、D1 への書き込みがいつも速いとは限らないため | Doherty の閾値、Nielsen #1 |
| **ゴールまでの距離を見せる** | 一括フォームでは未保存の件数（`SaveBar`）、書き忘れ（[pages.md 3-1](./pages.md)）を見せ、あと何をすれば終わるかが分かるようにする | ゴール勾配効果、Zeigarnik 効果 |
| **慣れた人の近道は足しすぎない** | 盤面の矢印キーのように、その画面の操作に自然なキーボード操作は入れる。独自のショートカットは入れない（覚えられず、読み上げソフトの操作とぶつかる） | Nielsen #7 |

### 2-3. 状態と知らせ

| 物差し | uma-memo でどうするか | 出典 |
| --- | --- | --- |
| **いま何が起きているかを見せる** | 送信中・保存した・未保存・共有中を、画面の上で区別できるようにする。成功の知らせと失敗の扱いは [frontend.md 第3章](./frontend.md)（成功はトースト、失敗は画面に残す） | Nielsen #1 |
| **エラーの文は直し方まで** | 「何が起きたか」と「どうすればよいか」を平易な文で書く。責める語・技術の語（ID・null・コード番号）を出さない。入力の誤りは欄の近くに出し、どの欄かが分かるようにする | Nielsen #9、GOV.UK（Error message） |
| **空の画面は次の一手を示す** | 0件のときは「まだ無い」だけで終わらせず、何をすれば増えるかと、そこへのリンクかボタンを出す（`RaceListEmpty`・`GradedRaceTrend` の書いていないとき） | Nielsen #10、GOV.UK |
| **競馬の言葉で書く** | 画面の語は競馬で通じる語（枠・馬番・上り・斤量・取消）を使う。アプリの中の都合の語（entry・note・withdrawn）を画面に出さない | Nielsen #2 |
| **説明は要るときだけ** | 説明を常に出すと画面が伸びる。毎回は読まない説明は `InfoTip` に畳む。取り返しのつかない注意は畳まない（[design-system.md 第6章](./design-system.md)） | Nielsen #8・#10 |

### 2-4. 誰でも使える

[evaluation.md 第3章](./evaluation.md) の Accessibility の観点を、設計の段階で先に満たすための物差し。

| 物差し | uma-memo でどうするか | 出典 |
| --- | --- | --- |
| **まず意味の合う HTML** | 移動はリンク（`<a>`）、その場で何かが起きるのはボタン。表は `<table>` と見出しのセル、入力のまとまりは `<fieldset>` と `<legend>`。役割の属性（`role`）で後から意味を足すのは最後の手段 | Inclusive Components |
| **開け閉めは disclosure で** | その場の段を開け閉めするだけのものは、`aria-expanded` を持つボタンにする（`EntryNoteEditor`）。`role="menu"` はコマンドを選ぶ `⋯` のメニュー（`DropdownMenu`）だけ | Inclusive Components（Menus & Menu Buttons） |
| **切り替えは状態か文言のどちらかで** | 押すと状態が変わるボタンは、`aria-pressed` で状態を伝えるか、文言を「推しにする」/「推しから外す」と変えるかのどちらか一方にする。両方を変えると読み上げが食い違う | Inclusive Components（Toggle Buttons） |
| **フォーカスを迷子にしない** | 開いた枠を閉じたら、開いたボタンにフォーカスを戻す。押したボタンが消えるなら、移す先を決めておく（`SaveBar` のフォーム） | Inclusive Components、WCAG 2.4.3 |
| **知らせは読み上げにも届ける** | 画面の一部だけが変わる知らせ（保存した・失敗した）は live region に出す（トーストと `role="alert"`） | Inclusive Components（Notifications） |
| **色だけに頼らない** | P7。枠・印・グレード・状態には字か形を必ず添える | WCAG 1.4.1、HIG（Color） |
| **動きは控えめに** | 動きを足すなら、どこから来てどこへ行ったかを伝えるときだけにし、`motion-safe:` を付けて OS の「視差効果を減らす」で止まるようにする | HIG（Motion）、WCAG 2.3.3 |

### 2-5. 見た目の階層

| 物差し | uma-memo でどうするか | 出典 |
| --- | --- | --- |
| **中身が主役** | 枠・飾り・説明文より、レースと馬とメモが目に入るようにする。飾りを足して整えない | HIG（Clarity・Deference） |
| **関係は余白と罫線で** | 関係の近いものは近くに置き、かたまりは罫線か `bg-muted` の1段で囲む。カードを入れ子にしない（[design-system.md 第6章](./design-system.md)） | 近接・共通領域、HIG（Layout） |
| **揃っていることに価値がある** | 揃った画面は使いやすく感じられ、少しの不具合にも寛容になる。逆に、画面ごとの小さな違いは「別のもの」と読まれる。同じ意味のものは同じ部品・同じ間隔にする | 美的ユーザビリティ効果、HIG（Consistency） |

## 3. 流行りの見せ方の扱い

流行りの見せ方は、**第2章のどの物差しを満たすかを言えるときだけ**入れる。「今どきだから」は理由にしない。
[design-system.md 第6章「避けること」](./design-system.md) に当たるものは入れず、入れたい理由があれば第0章のとおり決まりを変える案として PR に書く。

| 見せ方 | 扱い | 理由 |
| --- | --- | --- |
| 下に貼り付く操作の帯 | 使う。長い一括フォームの保存は `SaveBar` がこれ | 親指の届く場所に主な操作を置ける（2-2） |
| 下から出る引き出し（ボトムシート） | 今は部品が無い。`Popover` で足りないときだけ、`shadcn-svelte add drawer` で足す案を出す | 片手で操作できるが、部品を増やすのは下の段で済まないときだけ（[design-system.md 第1章](./design-system.md)） |
| 読み込み中の骨組み（スケルトン） | 最初の表示には使わない。続きを読む `LoadMore` のように、後から読むところだけ | 画面はサーバーで描いた HTML で届くので、最初の表示に待ちは無い |
| 押した直後に成功を見せる（楽観的な更新） | 保存には使わない | 失敗は画面に残す約束（[frontend.md 第3章](./frontend.md)）と、書きかけを失わないこと（P6）を先に守る |
| ページ遷移の動き（View Transitions） | 入れるなら、一覧から詳細のように「どこへ行ったか」が分かる場所だけ。2-4 の「動きは控えめに」に従う | 飾りの動きは中身の邪魔になる（2-5） |
| グラデーション・すりガラス・強い影 | 使わない | [design-system.md 第6章](./design-system.md) |
| ダークモード | まだ作らない | [design-system.md 2-3](./design-system.md) |
